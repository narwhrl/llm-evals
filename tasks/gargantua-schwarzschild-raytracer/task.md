# GARGANTUA — Schwarzschild Black Hole Raytracer

【任务】
从零制作全屏交互网站 **「GARGANTUA — Schwarzschild Black Hole Raytracer」**。使用 React、Vite、ES Modules 与本地 Three.js，交付可构建、可由静态服务器运行的完整项目。浏览器打开后必须直接看到黑洞全貌和吸积盘结构，不能出现黑屏、加载遮罩卡死或控制台错误。

实现只能写在 `tasks/gargantua-schwarzschild-raytracer/solution/`。不要修改本任务的 `task.md`、`README.md` 或仓库其他共享输入。

## 本地项目与交付边界

- 必须是 React + Vite 项目，采用 ES Modules；无需后端、账号、密钥或运行时网络服务。
- 必须使用本地 Three.js。候选目录必须包含受版本锁定的 `package-lock.json`（或等效锁文件）、完整源代码和 `vendor/`：`vendor/` 中保存运行时实际导入的 Three.js ESM 构建及所需 addon，`vendor/README.md` 说明上游版本、来源和许可证。不得把 `node_modules/` 当作 vendor 提交。
- 运行时不得依赖 CDN、远程贴图、远程 HDRI、远程音频、远程字体或 API；静态服务器离线提供项目文件后，场景仍必须可用。
- 在 `solution/README.md` 写清 `npm install`、开发启动、生产构建和静态预览的完整命令。`solution/RESULTS.md` 必须记录完整模型标识、起始 `main` commit SHA、实际运行过的命令和结果、浏览器验收结果、已知限制/失败及所需人工介入。

## 核心渲染：不可替代的物理主体

主画面必须由本地 Three.js 驱动的**全屏自定义 Fragment Shader**实时渲染。可使用 full-screen triangle 或 quad，但可见黑洞、吸积盘、星空和透镜效果都必须从该 Shader 的每像素求值中产生。

1. Shader 必须数值积分 Schwarzschild 度规中的零测地线，或采用数学等价且明确可追溯的稳定坐标形式。射线状态、积分步进、事件视界终止和曲率偏折不能只用一个解析弯曲贴图或预烘焙查找图替代。源代码应以命名函数/注释说明使用的坐标、状态量、步进与终止条件。
2. 必须真实处理事件视界、临界捕获边界和光子环：接近不稳定光子轨道的光线应形成清晰而深邃的临界结构，事件视界内部保持无发光的深黑。
3. 吸积盘必须沿积分后的弯曲路径求交，而不是渲染平面圆环；同一条光线在可见条件下须能收集并按路径顺序合成多次盘面穿越（至少首、次级像），形成高阶像/环状细节。
4. 星空和银河背景必须程序化生成并经过透镜映射；不得以图片、视频、屏幕截图、Cubemap 或环境贴图伪造背景或核心现象。
5. 盘面发射必须具有轨道速度导致的 Doppler 增亮/去增亮、引力红移、温度/亮度梯度和随时间变化的程序化湍流。不能只用静态橙色渐变或单层颜色环冒充。
6. 严禁以黑色球体、普通 Mesh 平面圆环、贴图、视频、截图、预渲染帧或其组合伪造黑洞主体。Three.js 几何只能承载全屏 Shader 和交互相机，不能取代零测地线渲染。

## 画面与后处理

- 使用 HDR 色彩工作流和可见的 Bloom，高动态吸积盘在不冲白的前提下明亮；使用 ACES（或等价、明确实现的 ACES tone mapping）。
- 加入克制的暗角、胶片颗粒和轻微色散；它们必须服务镜头感，不能遮挡光子环、多次盘面像或事件视界边缘。
- 保证黑洞核心深黑、吸积盘为高温明亮色、临界结构清晰。默认构图应具有可辨识的前后盘面和被引力透镜弯曲的背景。

## 相机、交互与 HUD

- 画面为全屏沉浸式渲染，加载完成即展示可读的全貌。提供可播放/暂停的电影镜头循环，且用户手动控制后不会失去控制权。
- 必须使用 `OrbitControls`。其相机位置、朝向和 FOV 必须真实传给 Fragment Shader 作为观察射线的输入；拖拽、缩放及触摸操作要实际改变透镜视角。
- 提供至少四个可点击且视觉差异明显的视角预设；在 HUD 中标明名称，并支持 `Shift+1` 至 `Shift+4` 直接切换。
- 提供可折叠 HUD，清晰显示质量档、调试状态、镜头状态和操作提示；桌面端不遮挡主要临界结构，移动端可收起或转为抽屉。
- 提供不少于 21 项可实际生效、可复位的参数控件。至少包括：
  1. 视场角（FOV）
  2. 相机距离
  3. 相机方位角
  4. 相机俯仰角
  5. 时间倍率
  6. 盘内半径
  7. 盘外半径
  8. 盘半厚度
  9. 盘温度
  10. 盘发射强度
  11. 轨道速度倍率
  12. 湍流幅度
  13. 湍流速度
  14. 恒星密度
  15. 银河亮度
  16. Bloom 强度
  17. Bloom 阈值
  18. 曝光度
  19. 暗角强度
  20. 胶片颗粒强度
  21. 色散强度

每个控制项都必须影响渲染或相机状态，不能是装饰性滑块。所有可配置状态（至少含上述参数、质量档、视角预设、HUD 状态与调试视图）必须版本化地持久化到 `localStorage`，并提供明确的重置入口。

## 调试、快捷键与可选声音

- 必须提供 `0` 至 `9` 共 10 个可切换调试视图；`0` 是最终合成画面，`1`–`9` 必须是可辨认且彼此有意义的诊断输出。至少覆盖射线/步进或终止、事件视界掩码、盘面交点及阶次、红移/Doppler、背景透镜坐标、星空/银河、后处理前 HDR 值等诊断信息。HUD 必须给出当前编号和说明。
- 必须实现并在 HUD 中列出：`0`–`9` 调试切换、`Shift+1`–`Shift+4` 预设、`Space` 播放/暂停电影镜头、`H` HUD 显隐、`R` 重置、`Q` 质量档切换。若实现氛围音乐，`M` 切换音乐；音频为可选项、默认不得导致浏览器自动播放错误，且音源必须本地或程序化生成。

## 质量、适配与故障恢复

- 提供 `Standard`、`High`、`Cinematic` 三档质量。三档必须真实改变渲染预算，例如内部渲染比例、最大测地线步数、盘面交点/采样数、Bloom 质量或后处理采样数，而不只是改标签。
- 支持移动端和 Retina：正确处理 resize 与 `devicePixelRatio`，在性能可控的前提下保留核心物理结构；触摸 OrbitControls、HUD 操作和质量降级必须可用。
- 处理 `webglcontextlost` 与 `webglcontextrestored`：丢失时暂停并向用户显示可恢复状态；恢复后重建 renderer/target/material 所需资源、恢复已持久化状态并继续渲染。不可通过忽略事件或自动刷新页面来规避。

## URL 截图自动化契约

实现下列稳定的同源 URL 参数，用于无人工截图验收：

```text
?capture=1&quality=high&preset=0&debug=0&time=12.5&hud=0
```

- `capture=1`：在首次可截图帧前关闭镜头循环和非确定性推进，使用 `time`（有限非负秒数，缺省为 `0`）冻结模拟时间，并关闭可选音频。
- `quality`：仅接受 `standard`、`high`、`cinematic`；`preset`：整数 `0`–`3`；`debug`：整数 `0`–`9`；`hud`：`0` 或 `1`。非法值必须安全回退到默认值，不能导致异常或黑屏。
- 页面成功完成 shader 编译、初次渲染和 URL 状态应用后，必须设置 `document.documentElement.dataset.gargantuaReady = "true"`，并暴露 `window.__GARGANTUA__`：至少包含只读 `ready`、`getState()`、`setQuality(level)`、`setPreset(index)`、`setDebug(index)` 和 `setTime(seconds)`。这些方法应验证输入并返回更新后的状态或拒绝非法输入，不应抛出未处理异常。
- 截图接口不能绕过核心 Shader 或用另一个静态结果代替正常渲染。
