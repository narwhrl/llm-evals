# CS PVP 雨夜货栈微缩沙盘：开发计划

## 目标

在 `tasks/cs-pvp-diorama/solution/` 内从零实现一个可本地构建、可在浏览器直接运行的 Three.js 三维场景。交付物是无可见 UI、无人物的全屏实体沙盘：完整正方形混凝土底座承载 T 出生点、CT 出生点、A/B 包点与三条清晰战术路线；桌面和触控均可环绕、拖拽和缩放；材质、灯光、反射、雨水与轻量动效共同形成冷峻雨夜的三渲二微缩质感。

## 已确认假设与范围

1. 任务是独立浏览器作品；共享基线没有 starter、测试或指定框架，因此使用原生 JavaScript + Three.js + Vite，不引入 React 或 UI 组件系统。
2. 所有纹理、标识、模型和动态效果均程序化生成并随构建产物打包；运行时不请求 CDN、远程模型、字体、图片或凭据。
3. “无任何 UI 界面”解释为页面只显示 WebGL 沙盘，不显示按钮、面板、加载器、标题或操作提示；画布仍提供不可见的语义标签、键盘操作和焦点状态。
4. “自由拖拽、旋转、缩放”通过 OrbitControls 实现：鼠标/触控环绕与缩放、受限平移、防止相机穿过底座；键盘提供等价的旋转和缩放路径。
5. 不实现人物、武器射击逻辑、碰撞漫游、炸弹玩法或 HUD；这些超出静态收藏级战术沙盘范围。
6. 视觉验收按仓库指定的 `1440 × 900` 视口进行，同时检查窄屏缩放和画布自适应。

## 架构与关键决策

### 技术栈

- **Vite**：只负责本地开发服务器和生产打包，保持入口简单、构建可复现。
- **Three.js**：场景图、PBR/Toon 材质、阴影、雾、OrbitControls 与程序化环境贴图。
- **Node 内置测试运行器**：验证布局数据、场景边界和关键区域/路线合同，不额外引入测试框架。

### 场景模块

- `src/main.js`：渲染器、相机、控制器、resize/visibility 生命周期和动画循环。
- `src/scene/layout.js`：40×40 底座、可建造边界、四大区域和三条路线的唯一坐标合同。
- `src/scene/materials.js`：共享色板、程序化噪声/标识纹理、Toon/PBR 材质工厂。
- `src/scene/primitives.js`：带轮廓硬表面、管线、线缆、楼梯和重复几何的低层构件。
- `src/scene/props.js`：箱体、油桶、托盘、车辆、路障、货架、灯具等可复用道具。
- `src/scene/regions.js`：底座、T/CT、A/B、中路、左巷和右侧高台的具体搭建。
- `src/scene/atmosphere.js`：雨丝、滴水、涟漪、蒸汽、灯光变化、雷光与动画更新器。
- `src/scene/world.js`：组装场景，集中管理动画、灯光、环境贴图与资源生命周期。

### 空间合同

- 底座：中心 `(0, 0, 0)`，平面尺寸 `40 × 40`，厚度约 `1.8`；所有可见实体限制在 `x/z = ±19.5` 内。
- T 出生点：北侧 `(0, -15)`；CT 出生点：南侧 `(0, 14)`。
- A 包点：西北 `(-11, -9)`，由半开放仓库承载；B 包点：东北 `(11, -8)`，由露天空地与两层门卫室承载。
- 中路：沿 `z` 轴贯穿，包含半开双铁门、射击孔、排水沟和两端掩体。
- 左侧绕后：沿西边界内侧连接 CT、A 与 T；右侧高台：沿东边界内侧连接 CT、B 与 T，并提供明显高差。
- 初始相机从东南上方观察全图，目标点略高于底座中心；限制极角与距离以始终保留“第三人称全景沙盘”读感。

### 美术与性能合同

- 冷蓝环境光为主；A 仓冷白灯、B 点暖黄灯、CT 红蓝警灯形成战术色温对比。
- 主体硬表面使用克制的 MeshToon/标准材质并附深色锐利轮廓；湿金属和地面使用低粗糙度 PBR 材质。
- 透明清漆湿地层配合程序化环境贴图和动态战术灯光投影表现反射，不增加逐帧离屏渲染通道。
- 重复道具共享几何和材质；雨使用单个动态 BufferGeometry；限制设备像素比并选择性投射阴影，避免逐帧分配。
- 动画由时间参数直接计算，不创建临时对象；页面不可见时暂停渲染。`prefers-reduced-motion` 下停止闪烁、雷光和环境位移，保留静态构图。

## 分阶段任务

### 阶段一：基础与可验证合同

#### 任务 1：建立可复现浏览器工程

**说明**：创建 Vite/Three.js 工程、全屏无 UI 页面、脚本和锁文件。

**验收标准**：
- `npm install` 后无需凭据即可运行。
- 页面 DOM 仅包含主画布容器及不可见语义内容，无可见 UI。
- 开发与生产入口均从相对路径加载，不依赖远程资产。

**验证**：`npm run build` 生成可部署产物；开发服务器返回页面。

**依赖**：无。

**预计文件**：`package.json`、`package-lock.json`、`index.html`、`src/styles.css`。

#### 任务 2：先定义并测试地图空间合同

**说明**：用数据声明底座边界、四区锚点和三条路线，先写会失败的合同测试，再补最小实现。

**验收标准**：
- 测试要求 T、CT、A、B 四个唯一核心区域存在且位于底座内。
- 测试要求中路、左巷、右侧高台三条路线连接正确端点且折点全部在边界内。
- 布局值只有一个事实来源，渲染代码直接消费该合同。

**验证**：首次 RED 明确因模块/合同缺失失败；实现后 `npm test` 全绿。

**依赖**：任务 1。

**预计文件**：`test/layout.test.js`、`src/scene/layout.js`。

### 检查点一

- 测试合同通过。
- 空白 WebGL 壳可构建、可加载且无控制台错误。

### 阶段二：完整拓扑与核心区域

#### 任务 3：搭建底座、中路与三条路线

**说明**：建立有厚度的正方形混凝土底座、湿地面层、中路门墙/排水沟/下水道口、左侧小巷和右侧高台。

**验收标准**：
- 任何观察角度都能读出完整正方形实体底座，底座外无场景几何。
- 中路、左绕后和右侧高台在俯视与斜视角度均连续可辨。
- 半开双门、射击孔、格栅排水沟、矮墙和高低差均可见。

**验证**：开发服务器浏览器多角度检查；边界合同测试保持通过。

**依赖**：任务 2。

**预计文件**：`src/scene/primitives.js`、`src/scene/regions.js`、`src/scene/world.js`。

#### 任务 4：完成 T 与 CT 出生区

**说明**：T 区加入铁网、集装箱、货车、梯子、斜坡、观察洞和桶/托盘；CT 区加入警用封锁、警车、高台、探照灯与装备箱。

**验收标准**：
- 南北出生区通过独特轮廓、道具和环境标识无需 HUD 即可区分。
- T 区具有两个集装箱高度和通人缝；CT 区具有可读的中路/B 侧双出口。
- 所有车辆、围挡和高台均在底座边界内。

**验证**：从默认视角和反向视角检查区域识别度与路线出口。

**依赖**：任务 3。

**预计文件**：`src/scene/props.js`、`src/scene/regions.js`。

#### 任务 5：完成 A 仓库和 B 门卫区

**说明**：制作可从全景看清内部的半开放 A 仓库与露天/半室内 B 包点，落实指定门窗、阁楼、楼梯、阳台和核心掩体。

**验收标准**：
- A 区有半卷卷帘门、木板窗、侧门、A 喷漆、货架/柱/阁楼和可见室内陈设。
- B 区有 B 喷漆、双门玻璃门卫室、办公陈设、消防梯/二楼阳台、路灯和转角捷径。
- 包点地面标识属于场景贴花而非界面，俯视和斜视均可读。

**验证**：分别将相机环绕到西北和东北低角度，检查室内外遮挡与层次。

**依赖**：任务 3。

**预计文件**：`src/scene/props.js`、`src/scene/regions.js`、`src/scene/materials.js`。

### 检查点二

- 四大区域与三条路线端到端可读。
- 全图轮廓紧凑均衡，入口、掩体和高低差没有明显阻塞或越界。

### 阶段三：细节、美术与氛围

#### 任务 6：铺设战术道具与环境叙事

**说明**：在不破坏视线的前提下放置箱、桶、纸箱、托盘、拒马、隔离墩、轮胎、自行车、垃圾桶、线杆、电线、排水管、编号、涂鸦与弹孔。

**验收标准**：
- 任务指定的主要道具家族均至少有一个清晰实例，分布服务于掩体与区域识别。
- 墙面/箱体存在货运编号、阵营喷漆、褪色标识和弹孔，但不形成视觉噪声。
- 线杆、电线、屋檐排水和道路小物保持在底座投影范围内。

**验证**：逐区截图检查道具覆盖与边界，远景仍保持路线可读性。

**依赖**：任务 4、5。

**预计文件**：`src/scene/props.js`、`src/scene/regions.js`、`src/scene/materials.js`。

#### 任务 7：建立三渲二湿夜材质与灯光

**说明**：加入共享色板、硬边轮廓、程序化磨损纹理、冷雨夜雾、暖/冷/红蓝灯光和选择性阴影。

**验收标准**：
- 主体轮廓清晰，混凝土、锈金属、湿沥青、木材、纸箱和玻璃能被快速区分。
- 默认全景同时出现冷蓝环境、暖黄 B 路灯、冷白 A 仓灯与 CT 红蓝警灯。
- 室内有足够明暗层次，亮部不过曝，暗部仍可辨认主要掩体。

**验证**：浏览器默认视角与夜间曝光检查；控制台无 shader/纹理警告。

**依赖**：任务 3–6。

**预计文件**：`src/scene/materials.js`、`src/scene/primitives.js`、`src/scene/world.js`。

#### 任务 8：加入反射、雨水与克制动态

**说明**：实现地面实时反射、细密雨丝、屋檐滴水、积水涟漪、蒸汽、灯光微闪、警灯交替、卷帘门振动和偶发雷光。

**验收标准**：
- 湿地面可见灯光与建筑反射，雨丝和涟漪在亮背景前清楚但不遮挡地图。
- 所有动画细微、循环稳定、无逐帧对象分配或几何增长。
- reduced-motion 模式禁用非必要位移与闪烁；正常模式满足任务动态要求。

**验证**：运行 60 秒观察稳定性、雷光周期和内存/控制台；检查湿地反光无明显闪烁或深度冲突。

**依赖**：任务 7。

**预计文件**：`src/scene/atmosphere.js`、`src/scene/world.js`、`src/main.js`。

### 阶段四：交互、验收与交付

#### 任务 9：完成全景交互与运行时约束

**说明**：配置鼠标、触控和键盘环绕/缩放，处理 resize、visibility、WebGL 降级文案与资源生命周期。

**验收标准**：
- 左键/单指拖拽旋转，滚轮/双指缩放；交互阻尼平滑、边界合理。
- 键盘方向键旋转，`+/-` 缩放；画布有准确的无障碍名称但没有可见操作 UI。
- 320、768、1024、1440 宽度下画布无溢出，场景比例不变形。

**验证**：浏览器实际执行各输入路径与 resize；观察焦点和控制台。

**依赖**：任务 8。

**预计文件**：`src/main.js`、`src/styles.css`、`index.html`。

#### 任务 10：生产验收、代码审查与结果记录

**说明**：执行最小充分测试、生产构建和实际浏览器验收，按五轴审查代码，并记录同基线结果。

**验收标准**：
- `npm test` 与 `npm run build` 成功。
- 生产预览在 1440×900 下从多个角度/缩放等级验证：无可见 UI、无人物、无底座外几何、四区三路完整、交互和动态稳定。
- `RESULTS.md` 记录完整模型标识、起始 main SHA、实际命令及结果、浏览器观察、限制和人工介入情况。
- 变更只位于 `tasks/cs-pvp-diorama/solution/`，并以符合仓库约束的逻辑提交收尾。

**验证**：审查生产产物网络/控制台、场景截图与 git 变更范围；提交后工作树干净。

**依赖**：任务 1–9。

**预计文件**：`tasks/cs-pvp-diorama/solution/RESULTS.md` 以及验收中确需修正的源文件。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 全景下建筑遮挡内部 | 高 | 仓库和门卫室采用半开放/切顶设计，关键陈设靠可见面布置，并从多个低角度复核 |
| 细节过多削弱路线识别 | 高 | 先锁定三路轮廓和视线，再填充道具；中央通道与路口保留负空间 |
| 湿地反光与阴影导致帧率下降 | 高 | 使用单层 PBR 清漆地面与共享投影纹理，不增加离屏反射通道；限制 DPR 并选择性投影阴影 |
| 深夜曝光使细节丢失 | 中 | 环境填充光与局部灯分层，使用 ACES 色调映射并在浏览器实景调参 |
| 轮廓线产生过量 draw calls | 中 | 只给主要硬表面添加轮廓，微型重复道具依靠明暗与材质边缘，不逐件描边 |
| 程序化标识在斜视角模糊 | 中 | 使用足够分辨率 CanvasTexture、MipMap 和贴花轻微离面，避免 z-fighting |
| 雨动画产生 GC/掉帧 | 中 | 单 BufferGeometry 原位更新；时间函数复用对象，不在动画循环创建数组/材质 |
| WebGL/浏览器能力差异 | 低 | 使用 Three.js 稳定 API、无实验扩展；构建与目标 Chromium 实际验证 |

## 开发顺序结论

依赖链为：工程壳 → 可测试布局合同 → 地形拓扑 → 四大区域 → 道具细节 → 材质灯光 → 动态氛围 → 交互与生产验收。每个检查点必须保持可构建且可浏览；任何视觉问题回到其源模块修正，不通过遮罩、截图或 UI 说明掩盖。
