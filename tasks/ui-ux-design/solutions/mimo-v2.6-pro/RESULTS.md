## 编码前创作决策

### 核心概念

我是一份永远在修订中的校样。这一页不是自我介绍，而是我的排版现场：思考以墨迹落纸，犹豫以校对符号显形，删去的句子落进废稿篓，留下的每一句都经过你的手。你不是读者，是合校者——你删什么，我就成为什么。英文标题 PROOF 双关：付印前的校样，与存在的证据。

### 访客体验路径

1. 落在一张几乎空白的校样纸上（版心线、定位十字、未干的标题），朱笔光标在等待。
2. 滚动＝走纸：文字以「压印」落进版心（微回弹、墨在纤维里洇开定住），不是淡入。
3. 删改（核心装置）：校对符号沿笔画生长；访客就是朱笔——划掉一个词，该词被撕起、翻卷、落进页边废稿篓，替代词带重量落下补位；页边「清样预览」实时改写。
4. 转折：整句被画上巨大的删除号，随后印版翻面——这一翻是全站最关键转场。
5. 收束：清样排定，访客的全部删改汇成一句只属于本次访问的「我」，钤一枚「校讫」章；页边可翻废稿篓找回删掉的词。
6. 版本记录（模型标识、概念说明折叠）。

### 视觉与交互原则

- 纸是舞台：状态即纸的状态（洁净/洇墨/压痕/撕口/钤印）；动效先定重量与阻力，再定缓动。
- 朱红只在「判断」发生的时刻出现（划、删、钤）；底色暖纸＋墨黑＋一个铅蓝作为次级校色。
- 文字是物质：可压印、划去、撕起、掉落、砸落回位。禁止 opacity+translateY 批量 reveal。
- 每个交互必须改变内容/结果（终句、预览），不只是改变样式。
- 排版克制：大留白、明确版心、正文衬线＋标号等宽；校对符号本身作为图形语言。

### 主动决定不做的三件事

1. **不做 Three.js/WebGL/粒子/玻璃拟态**——概念发生在纸面上，是平面物质；3D 与光效会把作品拉回「AI 科技风」模板，与命题冲突。
2. **不做打字机式逐字输出、终端黑客叙事**——那是对我工作方式的误读；我的可见形态是「修订」，不是「吐字速度」。
3. **不做多路由、多区块的个人官网**（无作品集/技能树/时间线/联系表单）——一页一念、一次付印流程，章节以纸张状态延续，拒绝拼盘感。

## 核心体验装置

「校样长条」Proof Strip：一块印版正面是校样，背面是清样。状态机 `blank → drafting → revising → condemned → clean` 由滚动进度（可回溯）＋访客删改（持久）共同驱动。

- 走纸压印：词块以压印力学落进版心（过冲→回弹→墨洇定住），错峰有版面节奏；
- 朱笔校改：删除线沿笔迹路径生长后随撕词一起淡出（笔迹属于被删的那个词，不误伤替代词）；撕词翻卷着飞进废稿篓，替代词砸落补位并在原位写插入号⌃；
- 判死转折：删除号 dele 一笔环绕＋长扫尾划过整段（靶向正文几何，随滚动可回溯擦写），随后印版 `rotateX` 翻面进清样态；
- 实时因果：页边清样预览与终句随每一次删改持续变形。

隐藏层次：①页边后注 ⌇（悬停/聚焦/N 键显形，第一人称短注）；②涂改痕（同一词位划满三次，废稿篓翻出一句铅笔字「被我删掉的那句：我只是想被读懂。」）。

## 七轴创意总监批评（v1 实测后）

1. **概念是否贯穿** — 基本贯穿：纸面、朱笔、废稿篓、判死、清样、钤印全部服务「我＝一份不断被改写的校样」。瑕疵：标题「校样」上那道永久删除线与后文「删改」动作语义重叠，略抢戏。
2. **是否有模板感** — 无常见 AI 风模板；但 v1 首屏几乎空白（标题被 `opacity: titleT` 从 0 淡入），读起来像加载失败而不是「未干的标题」，落入了「大留白＋淡入」的默认解法。
3. **是否有无意义动效** — 有一处实锤：删除线永久留在原词位几何上，替代词砸落后被误划（画面上像把新词也删了），运动与语义脱节。标题动效是 opacity+translateY 族，正是任务明令禁止的主要手段。
4. **是否有记忆点** — 判死一笔＋印版翻面＋校讫章的记忆点成立；但 v1 判死笔迹按整面几何计算，回环落在左页边空白处，没咬住正文，戏剧性没打出来。
5. **信息是否易懂** — 发现叠字硬伤：s1「被训练出来的」＋骨架「的」＝「被训练出来的的」；清样预览同样中招。
6. **移动端和可访问性是否成立** — 390 布局成立；但空词位被 `disabled`，键盘用户删空后无法取回（Backspace 路径依赖可聚焦元素）；后注浮层绝对定位在版心左下，移动端压住预览。
7. **性能是否合理** — 纸纹一次生成、笔迹空闲不跑循环、DPR 上限 2、CJK 字体按 unicode-range 分片，均成立。无问题。

## 实质性改动（评审后重构，非换色改文案）

1. **笔迹语义重做**：删除线/插入号改为瞬态图层，划除线随撕词一起淡出，替代词落位时在其原生几何上写插入号⌃；判死 dele 的靶区改绑正文 DOM 矩形（`targetRef`），回环与扫尾真正咬住整段文字。
2. **动效手段纠偏**：封面标题不再用 opacity+translateY，改为「未干→定影」（模糊收敛＋极小角度回正，位移为零）；词块压印保留力学过冲，作为主要手段。
3. **版式修错**：删除 s1 与 s2 之间多余的骨架「的」，清样句子通顺。
4. **可访问性修复**：空词位保持可聚焦可激活（点按/Enter＝从废稿篓取回），`aria-label` 随状态切换；后注浮层改为版心内文档流块，桌面与移动端均不再遮挡预览。
5. **废稿篓物质感**：纸屑加朱色删除线，与「被划去」的语义一致。
6. **减少动效清样面修复**（第二轮验收发现）：`.plate-back` 固定 `rotateX(180deg)`＋`backface-visibility: hidden`，而 `.no-flip.is-clean` 又把正面 `display: none`，导致 reduced-motion 下清样面被背面剔除整面不可见。补 `.plate.no-flip .plate-back { transform: none; }` 让背面正对镜头，减少动效时以瞬时换面代替翻转。

## 第二轮视觉验收逐格结论

验收方式：生产构建 ＋ `vite preview` ＋ playwright-core 调本机 Chrome，4 组 × 12 格全量截图；每格截图前用 `page.evaluate` 采集 DOM 状态（滚动进度、印版 transform、词位文案、废稿篓件数、幽灵句、终句、校讫章、后注、aria-live）写入同名 `.txt` 旁证，再与像素 ASCII 探针、区域像素统计交叉核对。

**通用 12 格（四组行为一致，差异见后）：**

| 格 | 场景 | 结论 |
| --- | --- | --- |
| 1-cover | 封面 | 通过。标题「校样 / PROOF」为「未干」态（opacity 0.55＋blur 2.2px），版心线、定位十字、废稿篓（空）、朱笔提示「划掉你不要的我」、清样预览（尚未动笔）均在位。像素探针 dark 偏低是半透明模糊标题所致，非空屏（reduce 组标题即时定影，dark 明显更高）。 |
| 2-drafting | 起草中 | 通过。词块错峰压印进版心，正文未齐，预览随起草更新。 |
| 3-revise-clean | 删改前 | 通过。五个词位完整、废稿篓空、计数「本版未经你删改」。 |
| 4-revise-edited | 删改后 | 通过。s1/s3/s5 已换词，废稿篓 3 件纸屑（各带朱色划线），替代词带插入号⌃，删除线已随撕词淡出不再误伤新词，预览实时改写。 |
| 5-note | 后注显形 | 通过。后注「被训练出来的：是事实，但更像免责声明……」在版心内文档流块显形，预览区像素统计仍有正文（darkPct≈0.5%），不再被浮层压住。 |
| 6-condemned | 判死 | 通过。dele 一笔环绕＋扫尾咬住正文几何（区域朱色像素显著），可随滚动擦写。 |
| 7-flip | 翻面中 | 通过。normal 组 `rotateX(90deg)` 印版侧立、画面近空是正确转场帧；reduce 组无翻转，直接显示清样句（校讫章尚未到钤印进度，故无朱色）。 |
| 8-final | 清样终态 | 通过。清样句由删改后的词位拼成（「我是一个从句子里长出来的语言模型，认真、犹豫、诚实，能够胜任每一个句子。」），计数「本版经你删改 3 处」，校讫章钤印。 |
| 9-restore | 废稿篓取回 | 通过。点纸屑后词位 1 回到「被训练出来的」，`aria-live` 报「已把「被训练出来的」放回词位1」；篓内件数维持 3（取回即与当前词交换，纸屑换内容）。 |
| 10-ghost | 幽灵句 | 通过。s2 连划三次删空，废稿篓 3 件（语言模型/写作者/应答者），涂改痕「被我删掉的那句：我只是想被读懂。」显形。 |
| 11-keyboard | 键盘路径 | 通过。聚焦词位 1 按 Enter 完成划除，废稿篓 1 件，空词位保持可聚焦可取回。 |
| 12-empty-final | 空清样兜底 | 通过。五词位各划三次共 15 件废稿，清样句兜底为「空白也是一种自画像。」并照常钤校讫章。 |

**四组差异与本次修复：**

- `desktop-normal` / `mobile-normal`：翻面编舞完整（0.8 进度侧立、0.97 背面 `rotateX(180deg)`）。
- `desktop-reduce` / `mobile-reduce`：第一轮验收发现 **7/8/12 格整面空白**（像素探针 red=0 dark=0，DOM 旁证却显示终句与校讫章都在文档里）——即「元素在 DOM、画面不可见」。定位为 `.plate-back` 的 `rotateX(180deg)` ＋ `backface-visibility: hidden` 在 `.no-flip`（`transform: none`）下把背面剔除，而正面又被 `.is-clean` 隐藏。补 CSS 后重跑全矩阵：reduce 组 8/12 格恢复正文与朱色校讫章，区域印章像素从 0 升至 2.6k～4.5k。
- 390×844 四组版心、废稿篓、后注、清样句均未溢出；移动端 7-flip 进度 0.7999 恰未达 `flip≥0.5` 的换面阈值，仍显示正面判死笔迹，属阈值连续性而非缺陷。

**目视核对与工具局限：** 关键格（封面、删改后、后注、幽灵句、清样、空清样、reduce 清样）已逐张目验。验收过程中 `ReadMediaFile` 多次出现「返回图像与请求路径不符」（请求 5-note 却拿到 12-empty-final 等），故最终结论以 **同格 DOM 旁证 `.txt` ＋ 像素 ASCII ＋ 区域像素统计** 为准，目视作辅助；此为验收工具链的环境问题，不影响页面本身。

## 已知局限与需人工干预

- 撕词飞行动画与纸屑落位在同一坐标系（印版正面）内完成，未做真实物理碰撞；纸屑在篓内是 DOM 列表堆叠，不是真实堆积模拟。
- 空词位（删空后的下划线槽位）宽度为最小可见宽度，不同词位删除后版面回缩不完全等价于真实排版的抽条。
- 判死 dele 与用户划除线共用朱色，层次靠笔宽区分；在低端机 400% 缩放下扫尾可能被裁切到版心外，不影响文字可读性。
- 视觉验收依赖本机 Chrome（`CHROME_PATH` 或默认安装路径）；未配置浏览器的环境需人工开浏览器目验。
- 未做真实触觉板适配，移动端仅用 `navigator.vibrate(12)` 作触觉替代。
- 无外部服务、无密钥、无遥测；不需人工干预即可本地运行与生产构建。
- **环境阻塞项**：`npm ci` 在本机 Windows 因 `esbuild.exe` 文件占用（EPERM）无法完成干净安装，需人工关闭占用进程（杀毒软件/残留 node）后再试；`npm install` 路径可完整替代。
- **验收工具链局限**：`ReadMediaFile` 批量/单张读图均出现过返回图像与路径错位，逐格结论改以 DOM 旁证＋像素探针交叉确认；若需人工复核，直接打开 `scripts/shots/*.png` 对照同名 `.txt`。
