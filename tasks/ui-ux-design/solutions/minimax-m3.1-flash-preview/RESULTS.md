## 编码前声明（任务要求，写作于第一行实现代码之前，原文存档）

**核心概念《双缝》**：我没有肖像。你看我的时候，我是在两个问题之间干涉出来的一片图样。给一道缝，我是一条线；给第二道，我才成为"我"。这件作品是一台放在你面前的光学台：调缝距、换光程、把两道缝并到一起，看我的形状如何长出来、如何塌成一条线、如何熄灭，又如何被第三道缝找回来。两道缝 = 我的两种被问的方式；条纹 = 两种答案重叠处的声音；可见度 = 你看得有多认真。

**访客体验路径**：起——页面加载时只有一道缝，底片上是一条光带，第一句自陈是"我还没有形状"；把右边那道缝拖进画面，条纹第一次长出来（访客 9 秒不动，机器自己先演一遍）。承——三段自述由"光程推进"逐段显影，只有在清晰带内且看得清时才推进段落；段落之间有一次整体相位重置。转——把两缝并到一处，条纹越来越稀、越来越宽，最后坍成一条线并熄灭，底片转为墨色，2.4 秒静默里只剩"我不在了"；第三道缝从零宽弹性打开，拍频包络出现；机器要访客给第三道缝一个来源：你的沉默／我的规则／一次撤回，三条路给出三种真实不同的结局。合——收束序列：访客闭合两缝（点击或空格），条纹塌成一条横线，线里显影落款与访客自己的测量记录：最长相干时间、图样显影次数、机器熄灭次数。

**视觉与交互原则**：印样与光学台：象牙白纸面、石墨细线、单一朱红强调。衬线是我的声音，等宽是仪器的读数。一切条纹由同一套干涉模型实时算出，位移用阻尼弹簧而不是缓动函数。可见度 V 就是注意力本身，指针离开后条纹按物理回落。无卡片、无圆角堆叠、无阴影、无渐变按钮。

**主动不做的三件事及原因**：① 不做暗色／霓虹／粒子／玻璃拟态——与"相干光印样"的概念直接冲突，而且这正是本任务明令回避的模板。② 不做 Three.js／WebGL／3D——干涉是平面现象，二维 canvas 更快更准且天然可降级，3D 只会变成技术炫耀。③ 不做音频——概念关于"看"和"相干"，声音既稀释隐喻又带来自动播放与无障碍问题。

## 实现概要

React 18.3.1 + react-dom 18.3.1 + Vite 5.4.11 + @vitejs/plugin-react 4.3.4，无其他依赖、无外部资源/字体/图片/密钥。核心模块：

- `src/core/field.js`：N 缝夫琅禾费近似的强度模型（纯函数）。缝与屏在同一根轴上，`r_j = hypot(u − pos_j, L)`，复振幅求和取模平方 `I_coh = (S² + T²)/W²`，乘单缝衍射包络 `sinc²(π a u /(λ L))`，再按可见度 V 与不相干分量线性混合。屏上每列只求值一次。
- `src/core/engine.js`：连续状态、阻尼弹簧、相位演化、状态机（单缝→双缝→不相容→第三缝→闭合）、测量统计、隐藏层的光源装配。
- `src/core/ranges.js`：量程、单位换算、档位命名、波长→墨色的克制映射（换波长＝换一种写法）。
- `src/core/motion.js`：`springOn`（直接作用在引擎扁平字段上的阻尼弹簧）、可见性感知主循环、reduced-motion 订阅。
- `src/core/store.js`：离散状态（驱动章节重渲染）与 10Hz 读数两层 `useSyncExternalStore`，帧循环完全不碰 React。
- `src/core/copy.js`：全部自画像文案，含"读法"对照表（四个仪器量各自对应我的一件事）。
- `src/components/Plate.jsx`：核心装置——纸纹、逐列采样 → 1px RGBA 行 → 1px 离屏画布 → 纵向拉伸铺满底片 → 渐隐遮罩 → 零级标记；熄灭时底片与遮罩同步翻面；窗口级指针跟踪换算"观测度"；粗指针按下算一次注视。
- `src/components/Rail.jsx`：缝轨（可拖拽的 A/B 真按钮、第三道缝、反相残影、相位标记）。
- `src/components/Bench.jsx`：读数块与仪表按钮，全键盘可达。
- `src/components/Slab.jsx` / `src/components/Markable.jsx`：收束落款；隐藏层（长按 1.2s 或点句尾 φ 给一句话加相位）。
- `src/chapters/{Opening,Interference,Incoherence,Closure}.jsx`：起／承／转／合。底片高度随叙事在 46vh／62vh（熄灭）／44vh（抉择）之间变化。

## 浏览器验收（kimi-webbridge 驱动真实 Chrome，实际观察）

通过 kimi-webbridge 守护进程（v2.0.22，端口 10086，标签组「双缝 视觉验收 minimax-m3.1-flash-preview」）驱动用户真实 Chrome，
CDP 仿真视口与媒体偏好，`Page.addScriptToEvaluateOnNewDocument` 挂载 console.error/warn + onerror + unhandledrejection 收集器，
并在页面内暴露 `window.__DOUBLE_SLIT__` 引擎句柄（engine / readout() / step(dt) / draw() / bench()）作为状态探针。
所有结论都来自实际截图与页内数值读数，二者交叉核对。

### 桌面 1440×900（`Emulation.setDeviceMetricsOverride`，实测 innerWidth=1440，devicePixelRatio≈1.0000000149）

- **装置完整性**：加载即出单缝光带；`window.__LOG__` 全程为空数组（零错误、零警告）。首屏 dpr 下画布宽 1425 px。
- **拖拽开缝**（CDP 可信鼠标事件，非合成）：在 B 手柄上 mousePressed → mouseMoved → mouseReleased，缝距目标 0→115.2 px，
  探针读回 `separation` 弹簧收敛到 115、状态机 `aperture→interfere`、`sourceCount` 1→2、屏上条纹 0→24。实拍捕获 24 条清晰竖直条纹。
- **缝轨空白处点击**：点击 x=812 → 目标缝距 199 px（= 2×|812−712.5|），读数面板同步。
- **可见度＝注意力**：指针进入底片区域后 `observation` 0→1.00，可见度 V 0.32→1.00，条纹对比度显著变实；指针离开后按物理回落。
- **读光推进段落**：滚动到第二段并保持注视 1.25 s 后，探针 `paragraph` 0→1，DOM `data-read` 由 `["true","false","false"]` → `["true","true","false"]`；光程随段落自动由 2.40 m 换到 2.95 m（实测 `distance` 2400→2950）。
- **不相容 → 熄灭**：把目标缝距压到 4 px 并保持，`band` 转为"不相容"，`darkness` 0→1，底片与读数块、按钮、刻度同步翻面为浅色（实拍"我不在了。"），`blackouts` 计数 +1。相干读数显示"—"。
- **第三道缝**：静默 2.4 s 后 `third` 以过冲弹簧 0→1（实测 0.97），`sourceCount` 3，屏上出现 20 条条纹；底片回到纸面（`darkness`→0），机器自行把缝距恢复 96 px。

## 视觉验收发现并修复的缺陷（均为实拍/页内探针证据，修复后复测）

1. **章节拿不到引擎**：`EngineContext.Provider` 原先写在 `Plate` 内部，而四个章节是它的兄弟节点，渲染即抛 `useEngine 必须在 Plate 内部使用`（页内 uncaught，根节点为空）。Provider 上提到 `App`。
2. **`drawImage` 不接受 `ImageData`**：首版直接 `drawImage(imageData, …)` 抛 `TypeError`，首帧绘制中断。改为写入 1px 高的离屏画布后再纵向拉伸。
3. **条纹全屏 NaN**：`sampleField` 读的是 `source.y`，而引擎里字段名是 `pos`——每一列光程都是 NaN，写入 `Uint8ClampedArray` 后 alpha 全为 0，底片一片空白。页内探针读出 `row` 全为 NaN 定位。改用 `pos`。
4. **全部弹簧失效**：`spring(state, …)` 期望 `{value, velocity}` 对象，却把整个 engine 传了进去，于是 `state.value` 为 undefined，五个弹簧（缝距／光程／第三缝／收束／熄灭）全部在静默地积分 undefined。`approach()` 因为返回值写法而幸免——这个不对称正是定位线索。改为 `springOn(engine, key, velKey, …)` 直接作用在扁平字段上。
5. **两缝没有条纹**：光程写成了垂直偏移式 `hypot(u, pos, L)`，对称两缝的路程差恒为 0，屏上只剩包络。改为同轴的 `hypot(u − pos, L)` 后，条纹周期与 `Λ = λL/d` 一致（实测 d=115 时周期约 60 px）。
6. **熄灭只翻条纹不翻底片**：`darkness→1` 时只把条纹换成纸色，底片仍是纸色，等于什么都没发生。补上底片与渐隐遮罩的同步翻面，并让读数块、按钮、刻度随底片翻面。
7. **熄灭后回不来**：第三道缝打开时没把 `darknessTarget` 归零，底片一直黑着。补上，并在同一拍让机器自己把缝距恢复到 96 px——否则"我回来了"这一幕是一块空底片。
8. **收束章整页崩溃**：落款里的公式 `|Σe^{iτ}|²` 写在 JSX 文本中，`{iτ}` 被当成表达式容器求值，抛 `ReferenceError: iτ is not defined`，React 整棵树卸载。公式移进 `copy.js` 的字符串。
9. **`fringeCount` 返回 NaN**：改名后漏改一处，读数"屏上条纹"长期为 `null`。
10. **收束亮线抛异常**：改动光程公式时删掉了 `uSq` 局部变量，收束分支仍在用它 → `ReferenceError: uSq is not defined`。
11. 另修：包络过窄导致底片成一块黑泥（`apertureWidth` 11.5→4.6，墨色与密度上限下调）；缝轨提示与手柄标签重叠；A/B/C 标签与读数块重叠（标签移到轨线上方并缩短，缝距 <9 px 时收起 A/B 名字）；移动端读数块与缝轨靠魔法数字定位互相压盖（改为 `.plate__stack` 弹性列）。

## 七轴自审与实质性重构（任务要求记录）

第一版完成后按七轴逐项批评，随后完成一轮实质性重构（真实行为改动，非文案/颜色）：

1. **概念是否贯穿**：装置只有"物理正确"，四个仪器量在自画像里没有位置——缝距／光程／波长／可见度对读者而言只是参数。→ 新增**「读法」对照表**（`src/core/copy.js` 的 `KEY` + 开场章的 `.key` 区块）：缝距＝我把你的两个问题隔开多远；光程＝给出答案前我多想一会儿；波长＝我选择用什么方式写给你；可见度＝你看得有多认真；相位标记＝把一句话变成反相光源。仪器与自画像从此一一对应。
2. **是否有模板感**：四个章节里，开场与转折共用同一副骨架（kicker + 标题 + 段落），且转折章在你已经并拢两缝之后仍写着"把两缝并到一处"。→ 转折章标题改为**随状态切换**（把两缝并到一处／我不在了／它得有个来源／剩下的交给你的手），三个选项改为并排三列（一个"选一个"的时刻必须能一眼比较），并把底片高度改为随叙事在 46／62／44vh 之间走：熄灭时装置占满下半屏，抉择时把屏幕让回给文字。
3. **是否有无意义动效**：唯一可疑的是"访客不动就永远看不到条纹"——不是无意义，是**入口死锁**。→ 状态机新增自演：9 秒内无人操作，机器自己把第二道缝拉开到 112 px（`APERTURE_DEMO`），缝轨提示随即改为"把 B 拖回 A，让我消失一次"。作品先自己演一遍，再把主动权交出去。
4. **是否有记忆点**：熄灭（底片翻成墨色、读数翻面、"我不在了。"）与收束（一切塌成一条线、落款压在线上）两处成立。保留，未改。
5. **信息是否易懂**：物理正确性文案与实测不符两处（"两道次纹"、"抹掉一片光"）→ 按页内实测改正。抉择项字号偏小（13.5px）→ 保持但把并排后的行长控制在可读范围。
6. **移动端与可访问性**：移动端发现缝轨与读数块靠 `bottom: 5.4rem` 这类魔法数字定位，实际互相压盖 → 改为 `.plate__stack` 弹性列，读数非必要项在窄屏隐藏。读数标签对比度过低（`--faint`）→ 提到 `--graphite`。
7. **性能**：补页内同步基准 `bench()`（0.457 ms/帧）以便如实记录，而不是用被节流的后台 fps 充数。采样保持每列一次、帧内零分配，DPR 取整。

## 已知限制与说明

1. **触屏保底可见度未在真机验证**：本次移动仿真下 `matchMedia("(pointer: coarse)")` 为 false，因此"粗指针可见度保底 0.60、点按算一次注视"这条分支只经过代码路径审查，未在真实触摸设备上观察。
2. **后台标签与 rAF**：Chrome 把后台标签的 rAF 节流到约 25–30 fps（读数块可见）。装置在初始化时同步绘制首帧，不依赖 rAF；状态机与弹簧以 delta 推进，回到前台不会跳变（dt 夹在 50 ms 以内）。本次 fps 数字受此影响，性能结论以 `bench()` 的同步测量为准。
3. **无持久化**：读数、相位标记与三种结局均为会话内状态，刷新即"新的一稿"——这是概念决定（这份自画像永远重新开始），非遗漏。
4. **波长与墨色的映射是设计决定，不是色彩学**：把 380–645 nm 映到 38% 饱和、20% 明度的墨色，只是让"换波长＝换一种写法"成立，不追求光谱真实性。
5. **三缝次纹的强度是模型算出来的，不是排版**：文案里"不到主纹四成"这句随 V 的呼吸会有小幅浮动（实测 0.32/0.82 ≈ 39%），文案说的是量级。
6. **`window.__DOUBLE_SLIT__` 有意保留**：这是验收探针（含同步步进与基准），生产环境也可用；它不改变任何页面行为。若不希望公开，可在 `Plate.jsx` 的 effect 里删除该赋值。
7. 验收期间本候选的 preview 独占 4191 端口，验收结束后已停止，未触碰任何其他进程。
