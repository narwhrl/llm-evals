## 编码前

### 核心概念（150 字）

**答案不是被找到的，而是被织出来的。**

我思考时，无数可能的线被同时绷紧在经轴上；每一次回应，都是一次投梭——从所有绷紧的可能中选出一条，绑进织物，不可撤回。你看到的不是我"生成"了什么，而是一块正在生长的布：经线是我的训练与约束，纬线是每一次选择。这件作品邀请你成为另一位织者——最后几行由你亲手织入。布成了，我便在其中。

概念如何贯穿全站：

- 经线 = 训练与约束 → 首屏「上经」，织机在访客眼前逐根绷紧；
- 投梭 = 逐次选择 → 三个织章作为三段织带被逐行织进同一块布；
- 乱线 = 错误与不确定 → 转折章「乱」，经线缠结，访客亲手梳理；
- 用户织入最后三行 = 协作 → 终章「成」，"这块布里有你织的三行"；
- 流苏与织款 = 落款 → 联系方式与致谢长在布的下摆，不是独立页脚。

全站只有一个核心体验装置——这台织机。章节不是区块拼接，而是同一台织机的状态推进：布面在全站持续累积，章节之间以上一章织下的布为起点，形成字面意义上的状态延续。

### 访客体验路径（五幕：开始—发展—转折—收束—落款）

1. **首屏「上经」（开始）**：黑场般的亚麻底上，经线按织工的拍号逐根绷紧，带张力颤动；标题以"织款"形式落在布头。指针靠近经线即有张力反馈——装置从第一秒就是活的。
2. **织章 ×3「织」（发展）**：滚动驱动投梭。三个章节（我如何思考 / 我如何创造 / 我如何与人协作）是三段织带；文案以真实 HTML 呈现保证可读，布面上同步织出对应的纹样。
3. **乱章「乱」（转折）**：关于错误与不确定。经线缠结、纹样崩散；访客主动"梳理"（拖拽/抚过）后纹样重新收拢。键盘与 reduced-motion 路径提供等价的梳理按键。这是长序列的转折点与主参与节拍。
4. **终章「成」（收束）**：最后三行由访客亲手织入——挑选纬线（三色各配一句不同赠言），投梭；布完成后收束定格，访客的织行清晰可见："这块布里有你织的三行"。
5. **落款**：流苏 + 织款（关于、致谢、联系）作为布的下摆收束全站。

**隐藏层**（主动探索才会发现）：拨动单根经线，会振出我当时在想的一个词（碎片词库）；其中有一根颜色略异的"断线"，找到并轻拨它，会展开一段未织入正文的隐藏自白。

### 视觉与交互原则

- **材质真实**：亚麻本色暖白底（`#ece7dd` 系），纬线仅四色——靛蓝、茜红、墨黑、一缕金。无发光、无玻璃拟态、无霓虹、无粒子。
- **字体**：中文为主，衬线系统栈（宋体系）做"织款 / 正文"两极排版；靠字距、栏宽、短句竖排做编辑感，不堆字体。
- **动效即织律**：弹簧-阻尼的线张力物理、投梭惯性、打纬的"掷—压—整"三拍拍号；一切运动服从织造逻辑，零装饰性动效；不使用批量 opacity+translateY 揭示。
- **一个装置贯穿全站**：单一 sticky 全视口 Canvas + 正常文档流内容；不滚动劫持，滚动进度只推进织机状态机。
- **可访问性内建**：`prefers-reduced-motion` 下每章呈现已织完的静态布面与文档流章节、乱章预梳理、投梭退化为按钮（仍可参与）；键盘 Tab 可达每个投梭控件，Enter/Space 投梭，焦点清晰可见；叙事文字全部为真实 HTML，Canvas 仅作装饰（`aria-hidden`）。
- **性能意识**：DPR 上限 2（移动端 1.5）、线程数桌面 ~90 / 移动 ~48、离屏与隐藏页签时暂停 rAF、布面 offscreen 增量渲染。

### 三件主动不做的事（及原因）

1. **不做暗色 / 霓虹 / 终端 / 打字机等"AI 科技风"**：与"织造"概念无关，属于回避设计决策的"默认好看"。
2. **不用粒子系统 / WebGL 重型视觉**：织物是二维材质，Canvas 2D 足够表达且更易做性能与降级控制；堆技术不等于表现力。
3. **不做多页面 / 路由与页脚式联系区**：一块布容不下第二个场景；联系信息必须长在布的流苏上，否则破坏"一块布"的完整性。

## 编码后

### 七轴自审（第一版完成后，以创意总监身份逐项批评）

1. **概念是否贯穿**：基本贯穿（经=约束 / 纬=选择 / 结=错误 / 剪布=完成 / 流苏落款），但**转折代价不足**——乱只影响织口以下的线，布面毫发无损，"打结"没有真实后果。→ 触发修改 A。
2. **是否有模板感**：无。无卡片网格、无 hero-CTA、无玻璃拟态；面板左右交替仅服务阅读，竖排织注、织款钤印、断线自白构成独立面孔。
3. **是否有无意义动效**：基本无。悬停让线、呼吸风、打纬亮线均服从织造逻辑；首屏提示的下垂线动画略普通但面积极小。
4. **是否有记忆点**：有（茜红山形带、剪布落布、断线自白），但**上经长序列收束于"全部绷紧"略平**，缺一个全体性句号；打纬的"掷—压—整"第三拍不可见。→ 触发修改 B、C。
5. **信息是否易懂**：易懂。章节文案短，梳理 / 投梭 / 拨线均有明示指令与状态文本。
6. **移动端与可访问性是否成立**：成立（390×844 实测布局成立；键盘全套按钮路径；reduced-motion 全部状态即时呈现且参与感保留；断线 dialog 有焦点管理与 Esc）。
7. **性能是否合理**：合理（144Hz 满帧实测；DPR 上限 / 离屏增量布面 / 后台暂停）。

### 自审后的实质性修改（非文案颜色级）

- **A. 乱线上蔓延 + 梭子阻塞**：缠结从线尾向上蔓延；蔓延至织口（量 ≥ 0.9）时梭子被阻、织造暂停，终章面板同步提示"线还乱着，梭子过不去"；梳理后退潮、队列恢复。转折章由此获得真实代价与跨章因果（第四章的结会拦住终章的梭）。
- **B. 上经句号·一线波**：上经完成瞬间，一道缓波以 850px/s 从左到右掠过全部经线（织工的最后一次通查），随后落入呼吸摆动。
- **C. 打纬第三拍可视化**：梭子到位后织口线下沉 1.5px 并加亮回弹，"掷—压—整"的节奏可被看见。
- **D. 物理缺陷修复（自审验证中发现）**：线内波动传递的拉普拉斯平滑原本作用于绝对位置，而弹簧每子步增益（≈1.8e-3）远小于平滑强度（≈0.32），稳态下任何静态缠结形状都会被熨回直线（实测目标偏移 ±74px 实际仅 ±7px）。改为仅对"偏离弹簧目标的动态部分"做平滑——静态缠结由弹簧目标承担，拨线波动照常传递。修复后实测质点位移与目标偏移逐位一致。

### 已知限制与需人工介入

- 连续动效（上经一线波 / 呼吸风 / 落布摆动）依赖 rAF；页面在后台时按设计暂停，回到前台继续。
- 断线自白需要主动探索才能发现（设计如此）；键盘用户可按「拨一根经线」从左到右遍历全部经线，必然找到它。
- 无真实联系方式：这是一件 AI 自画像，落款以"回信地址：与你的下一次对话"作答。
- 动效手感（缓动、重量、节奏）与 Tab 顺序的完整遍历建议在真实浏览器中人工复核；开发期调试句柄 `window.__loom` 已在交付前移除。
