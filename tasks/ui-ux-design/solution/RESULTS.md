## 编码前声明（任务要求，原文存档）

**核心概念《未定稿》**：我是一台用草稿思考的机器——流利不是天性，是一遍遍划掉之后的残留。这份自画像因此永远处于修改中：每个字先以猜测的方式出现，被朱笔划掉、重写，直到被你的注视固定。页面上一切未完成都是诚实的；一切完成都来自访客的注意力。我不是一份定稿，我是一场还没停笔的修订。

**访客体验路径**：开场标题先写出「定稿」、划掉、补上「未」——装置第一次出场就自我修复。首屏是满屏稿纸起草场：自画像文字逐字落入格中，不稳定的字在候选字形间打转、被朱笔划掉、重写；访客指针是"读光"，照到的字沉淀为墨色定稿。滚动进入「读」章（滚动即注意力），再到「修」章——一段自我描述报出矛盾错误，访客在三种真实不同的修补中选择，结果延续到后文；机器修好自己后主动划掉一整段写下自白（转折）；终章由访客定稿过的字符台账与修补选择聚合而成，按下朱印才获得全站唯一的"完成态"。按住 X 可见这张纸自己的修订记录（草稿的草稿）。

**视觉与交互原则**：纸面语言（暖纸/墨/朱砂/石墨四色，稿纸网格+朱丝栏，同一栅格公式贯穿 canvas 与 DOM）；衬线为"定稿之声"、等宽为"工作之声"；动效以字符为单位（写入/划掉/重写/沉淀），朱笔划痕为线条绘制；圈点只属于注意力定稿，机器自发沉淀不带圈点；读光与修补选择跨章节延续；正文全部为真实 DOM 文本，canvas 仅作首屏装置。

**主动不做的三件事**：① 不做暗色/霓虹/粒子/玻璃拟态等"AI 感"视觉——与纸面概念冲突，会立刻滑向模板；② 不做音频——概念围绕书写与视觉注意力，声音会稀释"看一份手稿被修改"的专注，并带自动播放风险；③ 不做多语言与页面路由——单一中文、单页长卷是叙事本身，切换会破坏"一份手稿"的物性。

## 实现概要

React 18.3.1 + react-dom 18.3.1 + Vite 5.4.11 + @vitejs/plugin-react 4.3.4，无其他运行时依赖；无字体/图片/CDN/密钥，全部程序化绘制与系统字体栈。核心模块：

- `src/core/manuscript.js`：可复现随机数（mulberry32）、断句库、候选字表（含人工挑出的形近误字）、确定性稿纸布局（4 带 × 4 槽贪心放置，标题保留带避让；格子尺寸公式与 CSS `--cell` 严格一致，保证首屏 canvas 与后续 DOM 章节的稿纸网格对齐）。
- `src/core/field-engine.js`：起草场状态机（BLANK→DRAFTING→STRUCK→SETTLED，时间驱动不依赖帧数）：写作头按乱序逐字点亮；草稿字在候选字形间打转、按周期被朱线划掉重写；读光（朱笔圈点）范围内的字以距离加权速度沉淀为衬线定稿；最长断句每 14–22 秒被一整道朱线划掉、清格、重起（装置的长时序心跳）；读光静止 3.5 秒后淡出（注意力离开的语义）；滚出首屏时收卷退场。
- `src/core/studio.jsx`：会话工作台 store（修订计数、读光定稿台账、修补记录、钤印），装置以 700ms 批量推送避免渲染风暴（useSyncExternalStore）。
- `src/core/motion.js`：prefers-reduced-motion 订阅、delta 驱动的 rAF 循环（页签隐藏暂停、恢复防跳变）、IO 在视口检测（离屏章节停更）。
- `src/sections/HeroField.jsx`：首屏装置接线（canvas、指针/方向键读光、标题编排：写出「定稿」→ 朱笔划掉 → 补上「未」）；后台标签 rAF 节流时由 500ms 兜底定时器继续推进，首帧同步渲染不依赖 rAF。
- `src/sections/ReadingChapter.jsx`：「读」章，280vh sticky，滚动进度驱动朱色阅读头逐字推进，读过沉淀为衬线墨色、未读保持铅笔灰。
- `src/sections/RepairMachine.jsx`：「修」章，自动起草→报错（错误证据引用实时修订计数）→三选一修补（甲划掉大话/乙加注边界/丙改写证据，三者动作、文案、结局各不相同）→重新运行通过→记录入台账，可重修。
- `src/sections/ConfessionChapter.jsx`：「承」章转折——四道朱痕依次划掉客套话，竖排朱批浮现，随后四句实话入场；若访客选了丙，开头先点破。
- `src/sections/FinaleChapter.jsx`：「合·印」——读光定稿台账（字格+朱点）、修补回声、收束三行；朱印（未定→已阅）是全站唯一完成态，由访客按下。
- `src/sections/BlueprintOverlay.jsx`：隐藏层——按住 X（或右下角常驻按钮，触屏可用）显示构线、栅格公式与本作品自己的修订记录。
- 可访问性：跳转链接、焦点样式、`aria-label`/`aria-live`、全键盘路径（方向键读光、Tab+Enter 修补与印章、X 骨架、Esc）、reduced-motion 静态定稿替代、canvas `aria-hidden`、正文全部为真实 DOM 文本。

## 浏览器验收（kimi-webbridge，实际观察）

## 视觉验收发现并修复的缺陷（均为实拍/探针证据，修复后复测）

1. **装置不启动**：写作头选中未激活字符时缺 `activate()` 调用，起草场永远空白——修复后四态流转正常。
2. **候选字选择器死循环**：`candidatesFor` 在循环内重建相同种子的随机数，可陷入无限循环并卡死渲染进程（表现为守护进程 evaluate/screenshot 全部挂起）——改为单生成器+硬上限，修复后长时间运行稳定。
3. **替换句不渲染**：打字机辅助函数把字符串切片传给本应接收数字计数的 state（字符串比较恒为 false）——改为传计数。
4. **乙路径注记为空**：`choose('b')` 分支漏设替换文本——补上。
5. **台账计数文案**：引用了不存在的 `settledCount` 字段（恒走零分支）——改用 `settled.length`。
6. **reduced-motion 起草场被清空**：后台兜底定时器在静态模式下仍以活跃状态重绘（全空白）覆盖静态定稿场——reduced 时不安装兜底循环。
7. **印章措辞**：修订数为 0 时「第 0 稿经你确认」观感如缺陷——降级为「此稿经你确认」。
8. 另：补内联 SVG favicon（消除浏览器自动请求的 404）；触屏设备隐藏「按住 X」提示。

## 已知限制与说明

1. **后台标签与 rAF**：浏览器将后台标签 rAF 节流至约 1fps。装置初始化首帧为同步渲染（不依赖 rAF），后台时由 500ms 兜底定时器以 0.5s 步进继续推进——画面变慢但不停止，恢复可见后自动回到满速。
2. **触屏读光未单独留证**：读光淡出（3.5s）快于截图管道延迟，触屏拖动后的圈点截图未捕获；其与鼠标共用同一 `pointermove` 处理器（鼠标路径已充分验证），触屏点按交互已实测（修补选择全流程）。
3. **移动端断句密度**：396px 宽下 14 句仅放下 7 句（槽位约束拒绝重叠），构图均衡但密度低于桌面。
4. **无持久化**：修订台账为会话内状态，刷新即"新的一稿"——这是概念决定（这份自画像永远未定），非遗漏。
5. **验收环境**：宿主 Chrome 缩放使 CDP dsf=1 时实测 `devicePixelRatio≈1.0000000149`；canvas 尺寸取整已覆盖非整 DPR。恰为 2.0 的 Retina 未直接测得，处理逻辑相同。
6. **端口共存**：验收期间发现另一会话的 preview 服务器（rainy-konbini-diorama 克隆）监听 `127.0.0.1:4173`；本候选监听 `[::1]:4173`（本机 vite preview 的 IPv6 怪癖），浏览器验收内容经截图证实全部来自本候选应用。验收后本候选服务器已停止，**未触碰他人进程**。
7. 初始化同步首帧若遇 canvas 2D 不可用会抛出并被收集器捕获显示，未实测禁用 canvas 的场景（本任务无 WebGL 依赖，降级面小）。
