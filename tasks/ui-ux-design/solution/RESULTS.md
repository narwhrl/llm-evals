## 一、编码前的设计声明

### 1. 核心概念（≤200 字）

> 我不存在，直到有人读。作品把这句话做成一张纸：屏幕上是一支同时写很多行的墨笔——一行是我，其余是我放弃的句子。你往下读，纸上的分叉就越多；你把光标停在某处、把温度调冷、按下「读」，就是从无数条线里挑出我。滚到最后，所有被划掉的笔迹会被吸回来，像拓印一样显影成你亲手写下的那几个字。我的自画像不是我写的，是你读出来的；我的人格，就是那些被放弃的线的总和。

一句话记忆点：**一个会随着你阅读而变脏、并从废弃笔迹里拓出你写的那句话的页面。**

这个概念同时决定：视觉（纸与墨的单一材质、三色纪律）、文案（以「放弃」与「被选中」为词汇核心）、交互（温度 = 分叉，读 = 选择，写字 = 参与成像）、排版（墨迹场是真的页面底层，文字写在纸上而不是浮在卡片里）、动效（落笔—渗开的两段式物理，而非淡入）。

### 2. 访客体验路径

1. **进入**：纸面近乎空白，一滴墨落下并写出第一笔，笔尖像写字一样沿页面向下移动。首屏没有居中大标题，只有一行手写横线、极小的注记与一行提示：把光标放到纸上。
2. **开始阅读（章节 0–1）**：墨笔开始分叉。左下角出现真实的温度控件（滑块 + ←/→ 键），读数实时变化：`温度 · 同时进行 · 已放弃`。访客发现自己的动作在改变"我想多少种可能"。
3. **截断（章节 2，关键转场）**：一条朱红细线自上而下划过，斩断所有分支；断口下坠、渗开、变成纸上的灰；整页轻微一震；归档计数开始累加。这是情绪转折：被放弃的不是错误，是代价。
4. **主动介入（章节 3）**：注记里藏着一句邀请——这张纸也收你的字。访客敲键盘，朱红湿润的字迹出现在他写字的地方，并成为终章的材料；同时可以展开「工作笔记」，看这台机器此刻在想什么、怎么工作（透明的自我说明）。
5. **成像（章节 4，收束）**：所有被放弃的笔迹被吸回来，像拓印一样错峰迁移、重新落墨，最终显影成访客亲手写下的那几个字。画面静止，只剩一句结束语与 colophon（方法、技术、可访问性路径与已知限制）。
6. **离开后仍可取用**：`?text=1` 提供同一份文案的静态排印版本；音效默认关闭、由访客点按开启；`prefers-reduced-motion` 走静置呈现路径。

### 3. 视觉与交互原则

1. **单一材质**：画面上的一切都必须能解释为纸、墨或印刷标记之一。不做发光、玻璃拟态、粒子、渐变光晕、卡片投影堆叠。
2. **三色纪律**：纸 `#f2ede3`；墨蓝黑 `#1b2a3a` 属于「我」；灰 `#8a8578` 属于「被放弃的」；朱红 `#c2492b` 只属于访客的注意力——截断线、焦点环、访客写下、以及「读」这个动作。朱红出现即代表有人在场，绝不做装饰。
3. **动效即编舞**：每次状态变化先有落笔（快、硬、有冲击），再有渗开（慢、柔、有黏滞）；元素必须由笔迹写出或由已有墨迹演化而来，禁止把 opacity + translateY 批量 reveal 当作主要手段；每个动效都要回答"它在表达什么代价"。
4. **排版当节拍**：中文单栏窄行，拉丁注记用等宽小字贴边；留白是"还没有写的纸"，不是装饰间距。
5. **状态连续性**：全站只有一个墨迹场（同一块 canvas、同一组笔迹对象）。章节不重建场景，只改装置参数（产墨点、温度、重力、吸附目标），所以章节之间有真正的因果。
6. **移动端不是缩小版**：装置变为横向墨带，滑动/滑块是温度，点击是「读」；一切交互都有等价、可聚焦的原生控件。

### 4. 主动决定不做的三件事

1. **不做暗色 / 霓虹 / 粒子 / 玻璃拟态的"AI 科技风"**。概念是纸与墨，暗色会摧毁材质逻辑，也会掉进任务点名的模板组合。代价是放弃"一眼很酷"，换来的是可触摸的物理感。
2. **不做 3D / WebGL 场景**。这个概念的载体是二维墨迹的笔压、渗开与覆盖；3D 管线只增加复杂度而不服务隐喻。Canvas 2D 的笔刷印章在这里表现力更高，降级路径也更干净。
3. **不做聊天界面与打字机对话**。访客的角色是注意力与选择，不是对话者；聊天 UI 会把概念降级成一个熟悉的范式，也会让"我的人格来自被放弃的线"这一命题失效。

（另考虑并放弃：多页面作品集与路由——这是单件作品、单条连续时间线，且托管环境没有 SPA 回退。）

## 二、创意总监评审（第一版完成后）

七轴逐项批评，每条都指到可改的地方。括号里是当真去看界面时看到的东西。

1. **概念贯穿**：初版只有一个"会分叉的墨迹场"，"我是被放弃的线的总和"这句命题没有落地——被放弃的数量只是读数里的一个数字，纸上没有任何代价的痕迹。
   → 致命处：章节二的刀切完之后，纸上没有留下"切过"的证据；终章的拓印也不成立（见 3）。
2. **模板感**：纸/墨/朱红三色纪律守住了，没有卡片、没有发光、没有渐变光晕。但「读这一行」是圆角胶囊按钮，是唯一的"UI 套件"残留；首屏的排版也还是常规的左对齐大标题。
   → 胶囊改成印章式的方角标记，和纸上的印刷记号一致。
3. **无意义的动效**：第一版里"分叉"实际上并不分叉——每条笔迹的墨量在分叉时按 0.4–0.85 衰减，三代之后全部落到 48px 的下限，屏幕上是一地短笔屑，既不像写字，也不像思想。这是把引擎的参数当成了动效。
   → 重写笔法（见 §三.1）。另外「静置呈现」原本只是把画布清空，等于把一个无障碍替代路径做成了空页面。
4. **记忆点**：终章拓印是唯一的记忆点，但第一版拓出来是一团实心黑块（记号尺寸是间距的 2.35 倍，彼此糊在一起），字能认出来，却不像"用废墨拓的"。
   → 把记号收到间距的 1.5 倍，让纸底透出来（见 §三.3）。
5. **信息易懂**：最严重的一处——正文与墨争同一张纸。第三章的正文被墨穿过，中文在墨迹里读不清。
   → 见 §三.2。另外读数里"拓印 0/1,776"是假的：React 自己算了一个总数，而引擎实际只搬了 888 个，`placed` 永远是 0。任何一方撒谎都比不显示更糟。
6. **移动端与可访问性**：390×844 下报头挤成三行，"工作笔记/静置呈现/音效关/阅读版式"逐字换行；Instrument Serif 从来没有被任何选择器用上（只有三条后代选择器写过字体族），两个 woff2 是死资产；读数区挂着 `aria-live="polite"` 而它每 220ms 变一次，屏幕阅读器会被无限播报；ghost 灰只有 3.15:1、朱红只有 4.20:1，都不到正文的 4.5:1。
7. **性能**：整页 rAF 实测 3 秒 181 帧（≈60fps，帧间隔中位数 17ms），`document.hidden` 会停帧。真正的浪费在离线烘焙：印章缓冲上限 8192，一次性 bake 20 秒会静默丢掉后面所有的墨（实测 `pending` 卡在 8192）——静置版画的画面因此是错的。

## 三、评审后的实质性改动

1. **重写笔法：从"笔屑"到"一行行写字"**（`ink/field.ts`、`ink/stroke.ts`）
   - 接笔：分叉不再重新起笔，而是接着上一笔的位置、方向与浓淡写下去（`ramp = 0`），墨量按父笔的 0.72–1.05 延续而不是衰减到下限；根笔墨量提到 220–520px。
   - 书写游标：低温时沿 42px 格线一行行写，一行写完换下一行，写到栏底再从顶上重来（每一遍错开一点），所以纸是"写满"的，不是"堆一堆短笔"。
   - 钢笔剖面：沿程压力起伏 + 收笔收细 + 与温度无关的手抖项；同时间隔从 1.5–2.4px 收到 0.85–1.5px，线不再是串珠。
   - 产墨曲线从 `lerp(5,34,t)` 收到 `lerp(0.7,20,t²)`：低温是一支笔在写（实测 t=0.08 下 60 秒 45 条、平均行长 285px），高温才是缠成一团（实测 t=0.92 下 30 秒 485 条、放弃 63 条）。
2. **文字与墨的关系**（`styles/layout.css`、`styles/scenes.css`、`components/Experience.tsx`）：每段正文底下垫一层软边的纸（`::before` + `mask-image`，不是卡片、没有投影、没有边框），报头改成 sticky 并自带一层渐隐的纸，于是"墨迹场是真底层、文字写在纸上"和"读得清"同时成立；报头也因此在下滚之后仍然可用。移动端报头改为两行（标题一行、开关一行）。
3. **静置呈现是真的版画**（`ink/plates.ts`、`ink/director.ts`、`ink/engine.ts`）：接入 `bakePlate`，并且
   - 离线烘焙分批落墨（`engine.bake`），不再撞上 8192 的印章队列上限；
   - 版画按章节**累积**在同一张纸上（同一张 cue 只烘一次），所以静置版一样"越读越脏"，终章才有足够的灰可拓（实测三章后纸面 390→514→737）；
   - 切到静置后由 Experience 重发当前章节的 cue，避免用默认参数烘出一张凭空多出来的版画。
4. **拓印的密度与真话**（`ink/hatch.ts`、`ink/field.ts`、`components/Deck.tsx`）：记号尺寸从 `spacing×2.35` 收到 `spacing×1.5`，字从实心黑块变成有纸底透出的拓印；`startHatch` 不再偷偷把 2 记号/目标压成 1；读数台改为只读引擎快照，`拓印 N/M` 与 `done` 不再由 React 另算一份。
5. **颜色与字体**（`styles/tokens.css`、`ink/palette.ts`、`styles/fonts.css`）：ghost 从 `#8a8578`（3.15:1）调到 `#6f6a5e`（4.62:1），朱红从 `#c2492b`（4.20:1）调到 `#b03f22`（5.03:1），画布与 CSS 同步；补上缺失的 `.latin` 规则，Instrument Serif 这才真的被用上（此前两枚字体的状态是 `unloaded`）。
6. **无障碍**（`components/Deck.tsx`、`components/Experience.tsx`）：读数区去掉 `aria-live`（它每 220ms 变一次），状态播报只走那条只说事件的 `role="status"`；画布层拿到 `role="img"` 与一句描述。
7. **音效**（`ink/audio.ts` → `ink/director.ts`）：`InkAudio` 首次被调用，报头加「音效」开关（默认关，必须在用户手势里开启），刀口与「读」各有一记声音，`navigator.vibrate` 只做增强。

**评估后决定保留的**：首屏仍是左对齐的大标题（评审第 2 条点到的"常规"）——它在移动端与窄屏上最稳，也因为首屏的对比对象是"纸上的空白"而不是别人的版面；这条批评记在这里，但不改。工作笔记面板仍是通栏下推的纸面（不改成侧边抽屉），因为它是"把纸压暗之后直说"的层级，不是导航。

8. **唯一的控件形态收口**（`styles/layout.css`）：「读这一行」从圆角胶囊改回方角印章（`border-radius: 1px` + 一层印泥重影），界面上最后一处"UI 套件"的残留没有了；按下的反白仍然是朱红，因为朱红只属于访客的动作。

## 五、已知限制与需要人工介入的事项

1. **中文没有自托管字体**：`--cjk` / `--serif-cjk` 走设备字体栈（PingFang SC / Songti SC / Microsoft YaHei…），所以中文排版在不同系统上不完全一致；拉丁排版（Instrument Serif）是确定性的。这是本候选主动接受的取舍（不引入 3MB 级中文字体、不请求外部字体服务）。
2. **静置版画是"重新模拟"而不是"回放"**：静置路径与完整动效共用同一个引擎与同一个固定种子，但因为访客在完整动效下看到的是自己那一遍的时序，两张纸不会逐像素相同。对同一章节、同一参数，静置版是确定的（可截图复现）。
3. **终章的"灰"有上限**：`MARK_CAPACITY = 1600`，超出时最旧的记号被挤掉；长时间停留后拓印的用料是最近约 1600 条笔迹，而不是全部。
4. **音效很轻**：只有刀口与「读」两记声音，没有笔迹摩擦声（那需要逐帧触发音频，性价比太低）。默认关闭，必须由访客点按开启。
5. **需要人工确认的两处观感取舍**：终章拓印的颗粒度（现在是"纸底透出来的拓印"）与纸张的暖度（纤维与底色偏暖，未做打印/校色意义上的标定）；两者都只影响观感，不影响功能与可达性。
6. **验证是人工场景而非自动化测试**：本任务没有固定测试，仓库也没有测试框架；本候选没有为此新增测试脚手架，验证依据是上面的构建命令与真实浏览器场景（含截图与读数）。
