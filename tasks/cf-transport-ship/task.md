# 任务：高还原度「运输船」浏览器第一人称枪战

**任务标识：** `cf-transport-ship`  
**文档版本：** 2026-09-28 / 本地 Agent 实施版  
**目标平台：** 桌面浏览器、键盘鼠标、本地运行、可静态部署  
**默认体验：** 《穿越火线》端游经典运输船地图、5 对 5 团队竞技、1 名玩家与 9 名本地电脑角色

## 1. 交付目标

在当前工作环境中，设计、实现、运行并验证一款具有完整对局流程的三维第一人称枪战游戏。以《穿越火线》端游经典团队竞技地图「运输船」为明确参照，将地图空间关系、主要掩体、交火视线、侧翼通路和第一人称观感尽可能准确地重建出来。[R01][R04]

玩家进入页面后，应能拿起有细节、有动画的武器，从出生舱走上甲板，在熟悉的货箱与集装箱之间移动、探身、点射、扫射、穿木箱、使用投掷物，与会移动和反击的对手完成一整局比赛。胜负、击杀、死亡、复活、弹药、声音和界面反馈，都由实际游戏状态驱动。

**成品以三个结果衡量：认得出运输船，打起来像一款成熟的竞技 FPS，连续游玩时保持稳定。**

投入优先级依次为：地图布局与尺度、移动和射击手感、电脑对手与对局闭环、第一人称武器和角色、材质与光照、界面和声音、环境装饰。各核心项均需完成；先后顺序用于组织实施。

### 1.1 默认范围

| 项目 | 本次要求 |

## 2. 先建立地图参照，再开始正式建模

### 2.1 版本与资料选择

以**端游经典运输船**为目标，优先采用同一时期、同一版本的俯视图和实机截图。手游运输船、手游 HD、CFHD、其他游戏的集装箱地图，以及第三方复刻，分别归档，不能混入核心布局参照。

文末提供了可直接检查的起始资料。R04–R09 包含俯视图、箱体近景、端部船舱和高处视角；R10 是 CF2.0 的画面资料，可辅助观察海天、吊机和环境表现，使用前核对版本差异。[R04–R10]

首先完成以下准备：

- 阅读并实际查看图片。记录每个资料的页面地址、图片地址、适用版本、可支持的结论及不确定点。
- 尽可能取得一段同版本连续走图视频，核验出生舱出口、侧道入口、转弯、高台和返回甲板的连接关系；记录有效片段时间戳。
- 建立 `docs/MAP_REFERENCE.md`，整理俯视轮廓、主要物体分组、通路、楼层、视线和固定对照机位。
- 将可保存的参考资料存入 `references/`，保留来源和文件校验值。参考截图用于分析与评审，和游戏实际使用的美术资源分开管理。

联网、视频或某张图片暂时不可用时，记录失败原因，利用已有可见资料继续推进。将缺证细节标记为待核验或近似重建；主体布局、移动、枪战和可用资源制作继续实施。

### 2.2 必须先辨清的空间关系

参考仓库的任务描述可以帮助理解目标，但具体地图事实仍需和游戏画面交叉核验。特别注意以下问题：[R01][R04–R09]

**中央货物的种类。** 起始实机图中能看见绿色篷布、绑带和木质底座的长形货物，也有波纹金属集装箱。建模时分别表现，避免把所有绿色长方体统一做成标准钢制集装箱。[R06][R08]

**通道的实际走向。** 区分舷侧通道、低位入口、管道内部、末端高台和返回甲板的位置。参考仓库提到的「地下道」应先核验其入口、出口和楼层关系；中央甲板下横贯两端的额外通道，只有在同版本资料支持时才纳入地图。缺乏证据时保持已确认的侧翼路线，记录这一差异。[R01]

**长视线的准确范围。** 核验从哪些门口或掩体边缘能够看到对面，以及看到的是门外、门框还是舱内。既要保留经典长距离对枪窗口，也要保留真实存在的遮挡。

**能站的位置。** 箱顶、平台、吊机附近构件分别标注为可站立、可跳达、可观察或背景装饰，避免将背景全部开放成新路线。

**两侧差异。** 保留箱体组合、斜放货物、端部舱室和高点暴露程度的实际差异。地图的整体平衡通过原有空间关系体现。

### 2.3 尺度与地图数据

在 `MAP_REFERENCE.md` 中定义统一坐标方向、阵营端点、甲板基准高度和比例尺。尺寸通过同一套资料的相对比例、人物高度、门框和箱体进行校准，估计值须标注。不要把推算出的米制尺寸称作官方数据。

地图的主要物体应有稳定标识，至少能够追踪：位置、旋转、尺度、物体类型、碰撞属性、弹道材质、是否可站立、参考来源。将以下四类信息组织成一致的地图描述：

1. 实际渲染的几何与材质；
2. 人物和投掷物使用的碰撞空间；
3. 射击、视线和声音使用的遮挡语义；
4. 电脑角色使用的可达区域和连接关系。

可以使用不同精度的几何实现上述用途，但同一堵墙、同一个箱子和同一个洞口的空间位置必须一致。修改主要掩体后，同步复核相应通路与视线。

**本阶段产出：** 一张标注后的布局图、路线连接图、关键掩体清单、一组尺度参数，以及固定对照机位表。完成后立即进入实现，后续用实机画面继续修正。

## 3. 地图重建要求

### 3.1 从第一人称就能认出运输船

完整呈现狭长货轮甲板、相对布置的两端出生区域、中场成组货物、两侧堆叠集装箱、木箱和高处平台。两端舱体、侧向围护、吊机、海面与天空应共同建立「在货轮上交火」的空间感。[R04–R09]

主要物体的位置、方向、间距和高度服从参考图。货箱排列采用确定布局；随机变化用于少量表面磨损和环境细节。

玩家第一次走出出生点，应能直接理解前进方向、近处掩体和主要交火区。不能用巨大空场、等间距货箱或一条无分岔走廊代替实际地图结构。

### 3.2 核心区域与验收重点

| 区域 | 必须呈现的空间关系 | 实机验收重点 |
| --- | --- | --- |
| 两端出生舱 | 内外层次、门口、门外缓冲空间、侧路入口 | 出生点安全落地；门框、墙面、顶棚均有正确碰撞 |
| 甲板主交火区 | 相向的长视线、可横向转移的空间、两侧掩体 | 能进行中远距离对枪，参考中的关键视线不被误加货物截断 |
| 中央斜置绿色货物 | 按俯视图确定夹角、间距与开口方向 | 形成可辨认的转角、射击缝隙和绕行关系 |
| 木箱与阶梯式箱组 | 明确的高低差、跳箱次序、箱顶支撑 | 小箱可合理跳上；高处依赖指定跳跃链到达 |
| 堆叠集装箱 | 大体量边界、局部入口、可达与不可达箱顶 | 视觉表面和碰撞一致，没有空中站立或穿箱 |
| 两侧绕行路线 | 各自入口、内部转折、出口与高处观察位置 | 连续走通已确认路线，电脑也能利用 |
| 高处平台 | 窄入口、边缘、高低视角和落回甲板的关系 | 可正常移动、蹲伏、射击、跳下；保留对出生区域的遮挡 |
| 低位空间 | 依照核实资料连接，不同楼层有清楚的高度关系 | 楼板遮挡射击和感知，寻路不会跨层直连 |

核心空间应以可玩区域为中心。船首、船尾、船壳、水线、外围海面和吊装设备承担环境完整性，不额外拉长主要对局路线。

### 3.3 碰撞与边界

人物在墙角、门框、斜置货物、集装箱接缝、台阶、高台边缘和低矮顶棚处，都需要稳定碰撞。斜箱的碰撞应贴合旋转后的形状，不能用过大的轴对齐方盒堵死旁边真实存在的缝隙。

玩家能够沿墙滑动、踏上正常台阶、在箱顶稳定落地。蹲下后改变实际碰撞高度；头顶受限时保持蹲姿。高速转身、低帧率、连续跳跃和斜向运动都不能导致穿墙。

可游玩区域的边界应与船体、围栏或舱壁对应。背景海域不扩展为游泳玩法。正常路径应防止跌出地图；异常越界设置受控恢复或死亡处理，并留下诊断信息，不能反复掉落。

装饰性缆绳、划痕、绑带和细小铆钉不应成为卡脚障碍。可见的大型掩体、实体栏杆构件与舱壁必须按照设定阻挡相应对象；网孔与实体部分的弹道行为保持可解释。

## 4. 美术与画面完成度

### 4.1 视觉基调

建立统一的写实工业海运风格：旧白色舱壁、低饱和灰蓝和橄榄绿货物、木箱的灰黄与褐色、深灰防滑甲板、偏黄的吊装结构，以及有层次的海天背景。具体配色和大色块分布以所选参考为准。[R05–R10]

默认采用能清楚辨认人物的日间光照。保留经典地图清晰、直接的视觉阅读，提高近距离物体的细节和光影。写实程度主要通过材质、尺度和动作实现，避免厚重后处理遮挡战斗信息。

### 4.2 模型与材质

- **集装箱：** 波纹板、边框、角件、门铰链和闭锁杆形成可辨识结构；旧漆、局部锈蚀、污渍和碰撞磨损具有方向与尺度。
- **绿色篷布货物：** 篷布褶皱、绑带、边缘收束和底部支撑具有层次；与金属箱的高光和粗糙度明显不同。
- **木箱：** 木板拼接、框架、钉件和木纹尺度自然；不同面保持合理纹理方向。
- **甲板与船舱：** 防滑钢板、接缝、排水格栅、扶手、舷窗和门框有近景细节；室内结构完整，光线能显示深度。

主要近景对象需要经过造型处理。程序建模可以作为正式资产策略，但必须产生有结构、有比例、有材质层次的结果。灰盒用于早期空间验证，最终交付应替换主要灰盒表面和轮廓。

允许使用自制资产、程序生成资产，或具有适用授权的第三方本地资产。使用外部模型时统一比例、材质和视觉风格，并记录来源。官方客户端解包资源及来源不明的模型、贴图和音效不纳入交付；品牌徽标和界面装饰使用自制图形。原版画面作为分析参照保留在独立参考目录。[R01][R03]

### 4.3 光照、海面和细节

阳光、环境光、阴影及必要的室内补光共同塑造物体体积。舱内可以比甲板暗，但人物不能消失在纯黑阴影里。接触阴影和环境遮蔽保持克制，避免箱底悬浮、阴影闪烁或严重条纹。

海面具有连续起伏、反射层次和远近变化。船体与海面之间的空间关系可信。环境风、海浪、缓慢运动的远景构件用于增强临场感；默认游戏相机和角色碰撞甲板保持稳定，避免船体摇晃损害瞄准。

准许加入低成本的海鸟、缆绳微动、缓慢移动的云和远处直升机等细节。它们不能遮挡关键视线，不能引入新的作战机制，也不能以明显掉帧为代价。重型天气、复杂镜面反射和电影式镜头属于核心体验完成后的加分项。

## 5. 第一人称操控与移动

### 5.1 默认操作

| 输入 | 行为 |
| --- | --- |
| 鼠标移动 | 第一人称观察；水平连续旋转、俯仰合理限位 |
| W / A / S / D | 前后左右移动，斜向速度归一化 |
| Shift | 静步，降低移动速度和脚步声 |
| Ctrl 或 C | 蹲伏，改变相机高度、碰撞体和可被命中的身体姿态 |
| Space | 跳跃，具备落地与可连续操作的反馈 |
| 鼠标左键 | 当前武器攻击；自动武器按住连发 |
| 鼠标右键 | 狙击开镜/切换镜倍率；近战重击 |
| R | 换弹 |
| 1 / 2 / 3 / 4 | 主武器、手枪、近战、投掷物；4 可循环已有投掷物 |
| 滚轮 / Q | 切换现有装备 / 切回上一件装备 |
| G | 快速投出当前选择的投掷物；消耗相应库存 |
| Tab | 按住查看双方战绩 |
| Esc | 释放鼠标并暂停本地对局 |

键位说明必须和实际行为一致。鼠标右键在游戏区域内不弹出浏览器菜单；游戏锁定时处理 Space、Tab 和滚轮，避免滚动页面或意外切走焦点。

### 5.2 视角与输入质量

由明确的「开始游戏」或「继续游戏」点击触发指针锁定，并处理锁定成功、失败和解除事件。退出锁定后显示可操作的暂停层，恢复需要用户再次点击。[R11]

鼠标朝向和角色移动立即响应。提供灵敏度设置、反转 Y 轴选项、独立狙击灵敏度和可调视野；明确视野设置采用水平还是垂直角度。窗口比例变化后保持空间比例和准星居中。[R13]

镜头只使用轻微、可关闭的行走摆动、落地反馈和受击抖动。开火后坐可以影响瞄准，但不应产生难以控制的长时间晃动。默认关闭明显运动模糊和强烈色差。

窗口失焦、切换标签页、暂停、死亡和结算时，及时清空按键、鼠标连发及待处理动作状态。返回游戏后不应出现持续向前走、自动开火或突然大幅转向。

### 5.3 移动与帧率

移动、加速度、重力、跳跃和动作计时独立于渲染帧率。30、60 和高刷新率下，移动距离和射速应保持一致。暂停时间不计入对局推进，恢复时不补算一大段滞后伤害。

人体高度、视点高度、台阶容许高度、箱体尺寸与跳跃高度统一调校。普通高集装箱应通过参照中的箱组或路线抵达；玩家能通过练习掌握跳箱节奏。小台阶可自然跨越，较高箱体保留明确的跳跃要求。

## 6. 武器、动画与射击手感

### 6.1 装备结构

每名角色携带一把主武器、一把手枪、一把近战武器、一枚高爆手雷和一枚烟雾弹。主武器在开始对局或等待复活时选择，随后在下一次出生生效。选择装备的界面展示清楚的武器轮廓和差异。

下表为本项目的**初始设计目标**。它们用于平衡和验收，具体数值在配置中记录，并根据实机体验调整；官方精确武器数值需另有来源支持。

| 类型 | 初始弹匣 / 备弹 | 必须有的体验差异 |
| --- | --- | --- |
| 高伤突击步枪 | 30 / 90 | 点射有力、后坐较明显，短点射和压枪扫射存在清晰差异 |
| 稳定型卡宾枪 | 30 / 90 | 更容易控制，连续射击的散布增长和回正节奏与上一把不同 |
| 冲锋枪 | 30 / 120 | 射速较快、近距离灵活，远距离伤害或精度明显逊于步枪 |
| 栓动狙击枪 | 5 / 20 | 开镜精确；射后有拉栓和再次开火间隔；腰射精度显著较低 |
| 大口径手枪 | 7 / 35 | 半自动、有明显单发节奏，快速点击仍受射击间隔限制 |
| 战术刀 | 无弹药 | 轻击与重击各有时机、范围和恢复时间，受距离与墙体遮挡约束 |

主武器之间的差异必须同时出现在射击表现、声音、动画和配置参数中。自动武器松开鼠标后立即停止连发。近战攻击有明确命中时刻，不能在挥动全过程逐帧重复扣血。

### 6.2 第一人称模型

玩家能看到有体积的持枪双手、手套、前臂和武器。持握关系、枪托、机匣、弹匣、护木、枪管、瞄具等结构合理；每种类型的轮廓一眼可辨。

模型分别完成持枪待机、行走、开火、换弹、切出、收起、狙击拉栓和投掷动作。换弹至少能看见左手操作和弹匣或装填部件的变化，动作关键时刻与弹药状态同步。可用程序动画或骨骼动画实现。

武器视角与世界视角可以分层渲染以保证近景质量。独立视模不能改变真实弹道：贴墙、靠箱或露出很小观察缝时，必须检查枪口受阻情况，防止枪身看似被抬起但子弹仍穿过实体墙。

### 6.3 后坐、散布与反馈

同时实现三个可区分的效果：枪械近景的机械运动、相机瞄准方向的后坐变化、子弹实际散布。准星扩张应表达实际精度状态，不能只有 UI 动画而弹道始终完全相同。

静止点射最容易控制，移动和连续射击提高散布，停火后逐步恢复；蹲姿可以适度改善稳定性。后坐具有可学习的主趋势，随机扰动保持适量。禁止用对准目标后自动命中的隐式吸附代替射击判定。

枪口焰、后坐、音效、抛壳、弹痕与受击反馈跟随真实开火事件。至少完成枪口焰、弹痕和抛壳三项。曳光为可选表现，并从合理枪口位置通向本次实际射击方向或碰撞点；不要把每发子弹画成贯穿地图的激光线。

### 6.4 开镜与换弹状态

狙击开镜真实改变观察视野与精度，具有清晰镜内刻线和合理外围遮挡。镜内外切换不应跳变到错误方向，退出后恢复原视野。开镜状态下的灵敏度和散布遵从相应配置。

弹匣、备弹、射击间隔、换弹进度、拉栓进度和切枪进度都属于实际武器状态。空弹匣、零备弹、反复切枪、暂停、死亡和重新开始均应覆盖。切枪不能凭空补弹，不能绕过拉栓间隔，也不能通过多次触发换弹增加总弹药。

## 7. 命中、穿透和投掷物

### 7.1 统一的战斗判定

玩家和电脑共享同一套开火、弹道、材质、伤害、护甲、死亡及计分规则。每次伤害都能追溯到攻击者、攻击事件、目标、命中位置和结果。

射击判定按空间中的实际先后遮挡处理。近处墙体、货物或其他阻挡物优先于其后的目标。角色身体采用与当前姿态同步的命中区域，至少区分头部、躯干和四肢；头部不能使用整个人物宽度的命中范围。

准星、相机射线与枪口出射关系在中远距离保持一致；近距离贴墙时合理处理枪口遮挡，避免眼睛能看见目标便无条件击中。

同一次击中不能因为命中多个网格三角形、头部与身体重叠、或多帧处理而重复扣血和计分。

### 7.2 生命、护甲与杀伤目标

默认出生为 100 生命与 100 护甲。护甲的吸收、扣减和不同部位规则在配置及说明中写清楚。头部伤害显著高于躯干，四肢伤害较低。

以 100 生命、无护甲、有效交战距离的躯干靶为基准，两把步枪约 3–4 发击倒；普通护甲可以适度增加所需命中数。栓动狙击在有效距离内的躯干命中具备一发击倒的威力，四肢命中保持区别。实际数值可在测试后调优，但必须保留上述武器定位。

受到伤害时显示生命/护甲变化、受击方向和短促反馈。击中、爆头、击杀分别产生可辨认提示。死亡由生命状态触发，附带短动画、计分和复活倒计时；死亡角色停止攻击和占用活体命中区域。

### 7.3 木箱穿透

建立明确的弹道材质分类。指定木箱能够被步枪和狙击穿透，穿透后降低伤害；厚钢制集装箱、实体铁箱、舱壁和甲板阻挡子弹。篷布货物的实际弹道分类根据参照与玩法设定记录，不能仅按颜色决定。[R01]

穿透需要有厚度或次数限制。能够找到入口、出口及出口后的后续命中对象；一发子弹最多穿透的厚度与物体数保持有限。木箱后还有钢壁时，子弹必须被钢壁截停。手枪和冲锋枪的穿透明显弱于步枪，具体规则写入配置。

正式验收应能在同一位置直接比较：无遮挡、木箱遮挡、钢箱遮挡三个条件下的命中与伤害。穿箱依靠这套真实判定，不通过单独的演示扣血逻辑实现。

### 7.4 投掷物

高爆手雷具有出手动作、真实飞行、重力、碰撞反弹、引信和爆炸。爆炸伤害随距离变化，并检查大型实体障碍遮挡；隔着厚舱壁的目标不能按纯半径计算承受完全相同的伤害。雷与人物的出生保护、友伤及自伤关系保持一致：默认关闭队友伤害，保留合理自伤。

烟雾弹落地后经过起烟、持续和消散阶段，形成能在实际交战中封住视线的烟雾区域。玩家在烟外、烟内和边缘都能观察到连续变化。电脑感知、敌人标识和小地图暴露逻辑遵从同一烟雾遮挡规则；浓烟后的敌人不能依然被电脑精确追踪。

烟雾通常遮蔽视线而不阻挡子弹。电脑失去视线后可以根据短时的最后已知位置进行有限压制，但不能持续获取烟后角色的实时坐标。烟雾需有明确有效范围，不能用整张地图变灰代替局部封烟。

投掷物在暂停、死亡、结算和重新开始时保持正确生命周期，不能残留到新的一局。

## 8. 电脑对手与角色表现

### 8.1 角色外观

电脑角色使用比例可信、具备头部、躯干、四肢、服装和持枪姿态的人形模型。两队通过服装配色、轮廓细节和友军标识可靠区分。交战中能辨认角色朝向、移动、蹲伏、瞄准、换弹和死亡。

身体模型、武器、动画和命中区域保持同步。步行时脚与地面关系基本可信；转向平滑但具有行动意图；避免悬空滑行、整身固定朝一个方向或永久保持伸臂姿势。

### 8.2 路线选择与战术行为

电脑使用地图的真实可达结构，能够从出生点出发、通过主要路线进入交战区、选择掩体、接敌、开火、换弹、转移和再次加入战斗。

一支队伍应出现主交火区推进、侧翼绕行和较远位置支援等不同倾向。保留随机种子以便复现，但正常对局有适当路线变化。整队不能永远挤在同一门口。

实际实现以下行为：

- 出生后及时离开出口，友军拥堵时让行、等待或重选局部路线。
- 沿甲板与已确认侧道行进，正确上下台阶和通道，不穿越集装箱或跨层瞬移。
- 接敌时尝试停射点、短点射、适量横移或退回掩体；枪口被掩体挡住时调整站位。
- 弹匣耗尽后换弹，适当借助掩体；切换目标保留合理转身与重新瞄准时间。
- 可在有效场景中使用有限的投掷物；投掷数量与玩家采用相同库存规则。
- 路径阻塞时检测无进展状态，先局部避障或重规划，不能持续撞墙直至整局结束。

高低层区域的寻路连接必须显式区分，投影位置接近不代表空间连通。跳跃连接只用于经过验证的箱组；角色确实执行起跳和落地。

### 8.3 感知、公平性与难度

视觉感知包含视野角、距离、实际遮挡和烟雾。声音感知依据附近开火、脚步和爆炸事件形成位置估计；其精度和持续时间低于持续直接观察。

发现敌人后存在反应时间、转向速度、瞄准误差和射击节奏。目标进入实体遮挡后，电脑保留短时最后已知位置，再搜索或转移。普通难度下，玩家通过静步、绕后、箱体和烟雾应能实质改变电脑行为。

提供简单、普通、困难三档。主要通过反应时间、瞄准误差、决策和协同频率调节难度；所有难度共享碰撞、生命、弹药、伤害、视线和移动规则。困难模式也不能通过穿墙跟踪或无视烟雾获得额外信息。

为调试保留可关闭的状态观察能力，显示当前路线、目标来源、最近可见时间和卡住状态。正式界面默认隐藏这些信息。

## 9. 对局流程与界面

### 9.1 完整流程

页面加载 → 资源准备 → 主菜单 → 选择队伍、主武器及难度 → 点击进入 → 出生 → 实际战斗 → 击杀或死亡 → 自动复活 → 达到结束条件 → 结算 → 再来一局。

默认先达到 **100 击杀**的一方获胜，最长 **10 分钟**；时间结束时比较比分，同分显示平局。菜单可提供较短练习局，但正式默认对局必须保留。达到结束条件后只触发一次结算，停止产生新的比分与战斗伤害。

默认死亡后约 3 秒在本方合理出生位置复活，恢复初始生命、护甲、弹药和投掷物。出生点从本方有效候选位置中选取，避免相互重叠和直接落在墙体中。短暂出生保护需要可见反馈；开火、主动攻击或离开出生保护区后立即结束，具体时长记录在配置中。

队友伤害关闭。默认友军实体阻挡子弹而不受伤，电脑在友军挡枪时调整位置；友军移动采用让行或软碰撞，避免堵门。敌人之间保持明确的身体占位。双方电脑之间的击杀同样计入比分。

### 9.2 界面布局

游戏画面占据主要视口。HUD 简洁、紧凑，在 1440×900 和 1920×1080 下均能清晰阅读：

| 位置 | 内容 |
| --- | --- |
| 中央 | 准星、短暂命中/击杀提示；狙击镜为相应武器状态 |
| 顶部中央 | 双方比分、目标分、剩余时间 |
| 左上 | 来自实际地图的简明小地图、玩家朝向、友军位置 |
| 左下 | 生命、护甲、必要状态 |
| 右下 | 当前装备、弹匣、备弹、投掷物库存 |
| 右上 | 有长度和保留时间限制的击杀信息 |
| Tab 面板 | 双方成员、击杀、死亡、得分等实际战绩 |

小地图的墙、箱体、路线和高低层应与实际场景对应。默认展示自身和友军，敌人不常驻显示。若采用开火暴露机制，敌方暴露点使用事件发生位置、短暂持续，并遵守明确规则；不要把它实现成持续实时追踪。

菜单、暂停、设置、死亡和结算界面视觉一致。菜单可使用当前地图的实时背景，但应优先保证快速开始游戏。按钮全部连接真实功能；可见的开关、滑块和选项必须生效。

### 9.3 设置与恢复

至少提供：鼠标灵敏度、狙击灵敏度、视野、总音量、音效音量、画质档位、镜头晃动开关。设置保存在本地，下次打开恢复；保存失败时保持当前会话可用，并提供合理反馈。

加载阶段显示实际进度或当前步骤。关键资源失败时展示具体错误和重试入口。WebGL 不可用时显示明确提示，保持页面响应。

桌面键鼠是必验收平台。触屏设备可以提供说明与观赏入口；如增加触屏操作，应使用独立输入适配，并完整测试对桌面逻辑的影响。

## 10. 声音与临场感

首次用户交互后初始化或恢复音频，遵守浏览器的音频播放限制。[R12]

至少具备：各武器射击声、空仓提示、装填/拉栓声、切枪声、金属甲板脚步、跳落声音、手雷爆炸、命中/击杀提示，以及轻量海风海浪底噪。自制或程序合成音效需要形成可信的瞬态、余响和层次，避免所有武器都像同一种提示音。

远近枪声、左右方向和遮挡应有可辨变化。玩家转身后，空间音源方向随相机朝向正确更新。舱内和甲板的声音可以有适度区别；环境音量保持低于关键战斗提示。

脚步声由真实移动与落脚节奏驱动，静步和蹲伏相应降低声音。枪声与开火事件同步，换弹音效与动画关键时刻同步。对大量同时开火、爆炸和快速重开控制最大并发音源，及时回收已结束音频节点。

## 11. 技术、性能与运行约束

### 11.1 技术基线

使用 **Three.js + Vite**；推荐 TypeScript。界面使用原生方案或现有 React 项目均可。优先复用已有工程惯例，锁定经过验证的依赖版本。Three.js 功能和加载器的用法以实际安装版本的官方文档为准。[R13]

对局、电脑、物理和声音逻辑在浏览器本地完成。依赖通过包管理器安装，模型、纹理、字体、音频及所需解码器随项目本地提供。生产运行不能依赖外部图片防盗链、临时下载地址、付费 API 或密钥服务。

提供开发、构建、预览、测试和类型检查命令。Vite 生产构建必须接受 `--base` 与 `--outDir`，在根路径和非根子路径均可加载所有资源。[R14][R15]

用户通过本地 HTTP 服务打开游戏。README 给出准确步骤，生产包也应能通过普通静态服务器运行。自动部署到公网不属于本任务默认操作。

### 11.2 工程组织

将地图数据、碰撞与空间查询、角色控制、战斗、电脑决策、视模动画、音频、HUD 和对局状态组织成职责清楚的模块。规模适中的模块足够，不需要为本任务建立通用引擎平台。

实体生命周期、事件订阅、计时器、粒子、弹痕和音频节点有明确创建与释放位置。渲染循环中减少不必要分配；重复货箱、装饰和粒子可复用或实例化。小地图及低频感知更新不必与每个渲染帧绑定。

主要掩体与角色使用合适的空间查询加速，避免每次开火或每名电脑感知时遍历大量装饰网格。弹痕、抛壳、烟雾粒子和尸体具有数量上限与回收策略。设定可见对象预算时优先保留战斗角色、掩体轮廓和武器清晰度。

### 11.3 性能目标

默认中等画质以 **1440×900、渲染像素比 1、完整 5 对 5** 为主要测试条件，争取稳定接近 60 FPS。另测 1920×1080。高画质可以提高阴影和细节，低画质首先减少后处理、阴影分辨率和环境粒子，保持地图、角色和玩法一致。

在实际有图形界面的浏览器中，预热后记录至少 120 秒：平均 FPS、帧时间中位数与 P95/P99、明显卡顿、绘制调用数及可取得的资源统计。写明 CPU、GPU、操作系统、浏览器版本、视口、画质和像素比；无法读取的项如实标记。

性能目标依据实际环境评估。软件渲染、无 GPU 或自动化环境的数据需要单独标识；不能当作普通玩家硬件结论。界面若显示 FPS，必须来自测量。

重点检查连发、烟雾与多名电脑同时交战时的稳定性，以及连续游戏和重复重开后内存、对象数是否持续增长。网络下载完成后的首局仍应覆盖着色器或动画首次使用的卡顿。

## 12. 实施顺序与自主迭代

先用一屏左右说明当前环境、参考版本、目录位置、关键实现策略和阶段安排，随后直接开始实施。一般工程选择自行决策并记录；确实需要权限或缺少无法替代的必要输入时，再提出具体问题。

### 阶段 A：参照与比例

核验资料，建立布局和路线记录，完成基础船体、舱室和主掩体。可以暂用灰盒，但必须能通过固定机位比较位置、角度、宽度、高度和交火视线。

**阶段检查：** 全部已确认通路可达，关键射线关系正确，人物尺度与箱体一致。此时修正布局的优先级高于制作细碎装饰。

### 阶段 B：可玩的战斗纵切片

完成玩家移动、碰撞、一把完成度较高的步枪、一个能自主移动和反击的敌人、真实伤害、死亡与复活。立即打开浏览器连续实玩，修复输入、贴墙射击、箱角卡住和命中偏移。

**阶段检查：** 从进入页面到击杀、被击杀、复活的流程真实成立。确定的状态、弹道和空间系统供后续扩展复用。

### 阶段 C：完整对局

扩展到默认 5 对 5、多路线电脑、全部装备、穿透、投掷物、护甲、计分、时间、暂停和结算。加入核心逻辑测试与可重复测试场景。

**阶段检查：** 不干预生命和比分，完成一局；双方电脑能够实际取得击杀，主要通路有不同角色利用。

### 阶段 D：高完成度呈现

替换主要灰盒，打磨武器、手部、人物、动作、材质、光照、空间声音与中文 HUD。使用相同机位比较参考图和实现画面，修正大色块、掩体比例和第一人称视觉。

**阶段检查：** 主要近景达到正式游戏资产的完成度；画质改动没有引入碰撞、可见性或性能回退。

### 阶段 E：独立视角复审与修正

至少完成一轮地图/美术复审和一轮实玩/工程复审。具备子 Agent 时，可分工做地图核验、资产、游戏逻辑或验收；明确文件边界，共享坐标、单位、接口与材质约定，由主 Agent 统一集成。资源有限时按同一顺序自审。

每轮选出最影响体验的 3–5 个具体问题，给出截图或复现步骤，完成实质修复并回归。优先修正地图失真、动作生硬、电脑卡路、射击不准、输入异常和明显掉帧。

**阶段检查：** 运行生产构建和验收矩阵，保存真实证据，整理交付说明。完成构建后继续验证生产预览，与开发环境分别记录。

### 13.1 自动化与实玩结合

为弹药守恒、伤害部位、最近遮挡、材质穿透、护甲、死亡幂等、计分、对局结束和重置编写可运行测试。随机过程使用可配置种子，记录测试用种子。

可以加入开发专用的测试入口，用于固定机位、设置场景、生成静止测试靶、驱动正常输入和读取状态快照。此入口复用生产中的碰撞、战斗和对局逻辑，不能通过直接改目标生命或比分代替正常交互验证。正式默认界面隐藏调试内容。

浏览器自动化优先走真实输入和页面交互。工具无法完成原生指针锁定或连续人工操控时，将相应验收项保留为未验证，说明已经覆盖的替代测试和所需人工步骤。不得将替代输入测试记录成已经完成真实鼠标锁定实玩。

### 13.2 必须保留的视觉证据

保存一张俯视布局图，以及至少以下 10 个运行视角：两端出生出口各一张、两侧主要交火位置各一张、两条侧翼路线或出口各一张、中央斜箱近景一张、高处俯瞰一张、持枪交战一张、结算一张。

地图对比使用固定机位，记录位置、朝向和视野；尽可能匹配参考图中的构图。额外保留换弹、狙击开镜和烟雾场景的截图或短录像，便于核查近景资产与特效。

截图全部来自实际运行版本。用于介绍的截图应保留真实光照、对象和界面；不得通过独立静态画面、图片覆盖或只针对截图模式的模型替换提高表面质量。

## 15. 质量评审与完成条件

### 15.1 硬性完成条件

以下条件共同构成核心交付门槛：游戏可进入；第一人称可移动和射击；地图主要路线可通行；实体掩体正确挡人挡弹；电脑实际作战；生命、弹药、死亡、复活和结算真实运行；默认 5 对 5 可完成一局；生产构建和本地资源加载可用。

严重穿墙、永久卡住、静态靶充当电脑、烟雾只改外观、比分按时间自动增加、资源失效、主流程按钮无功能等问题，必须优先修复。真实未解决的问题保留在交付报告中，不能用隐藏按钮、移除测试或降低验收要求获得通过。

### 15.2 评审权重

| 维度 | 权重 | 观察重点 |
| --- | --- | --- |
| 地图还原 | 35 | 布局、相对尺度、斜置掩体、端部舱室、侧翼连通、交火视线及固定机位相似性 |
| 枪战与操作 | 25 | 输入响应、碰撞、跳箱、枪械差异、后坐散布、穿透、投掷物和战斗反馈 |
| 视觉与声音 | 20 | 材质、光照、人物、手部武器、动作、空间声音、HUD 可读性 |
| 电脑与对局 | 15 | 多路线行动、公平感知、有效反击、换弹掩体行为、节奏、复活与结算 |
| 稳定性与交付 | 5 | 性能、重置、构建、本地资源、文档和验证证据 |

这些权重用于组织评审，不能用分数抵消核心流程失败。自评应以发现问题和修复为主；没有独立评审或同一标准下的对照测量时，不宣称「官方级复刻」「百分之百还原」或确定的相似度百分比。

**最终检查问题：一个熟悉运输船的玩家，在正常第一人称游玩中，能否凭空间关系认出地图，并愿意连续打一整局？围绕这个问题完成最后一轮打磨。**
